# 0012：第一期系统通知

- 日期：2026-11-26。
- 状态：源码实现，本地验证；正式部署与真人验收另行执行。
- 起因：用户指出存储预警需要专门通知入口，随后要求管理端和桌面端统一入口、样式；明确不处理 iOS 和远程推送。

## 体验与范围

两端顶部右侧共用 `packages/ui` 的小铃铛和 shadcn Dialog 居中弹窗，保持现有顶部栏高度。有未读时显示圆点，用户主动打开后查看内容、时间、已恢复或已处理状态，并可逐条或全部标为已读。用户随后明确要求通知自动更新、不展示刷新按钮，并使用弹窗而非侧边栏，因此更新与失败重试都在后台进行。通知不自动打开、不抢当前输入焦点、不播放声音。空列表只显示文字，中英、外观和键盘行为复用共享组件。

管理端接全站内容预算、磁盘余量、测量不可用及恢复；存储区域保留当前异常的紧凑提示，不再在概览顶部重复放大横幅。预算提前预警使用语义橙色，预算用完、磁盘严重不足使用错误色。

桌面端接本机接收失败、其他终态传输失败、网络下载失败或中断，以及服务端确认登录失效；主动取消、常规保存成功、复制成功和即时表单错误不进入通知历史。只有明确的本机写入空间错误才称本机空间不足，不能把对方磁盘不足归咎本机。过期任务历史保留，但任务已不在当前名单时不提供失效跳转；现存任务可清除对应页面搜索并定位。

## 数据与权限

新增独立的 `assemble-protocol::system_notifications` 类型，使用具名内容和标识，不承载任意 HTML、URL、路径、令牌或 Rust 诊断。既有日程通知、设备事件枚举、iOS 契约、远程推送和系统通知权限均不改变；第一期不把日程通知再复制一份。

通用有界账本在 `assemble-store::notifications`，问题状态与已读分开。持续问题按来源和资源合并，普通测量更新保留已读；恢复、严重程度变化会产生新版本并恢复未读。请求只承认用户实际看到的版本，迟到请求不能读掉后来变化。恢复后五分钟内再出现更新原条目，避免阈值附近反复生成多条历史；更久后重新触发可以形成新事件。每范围保留最多一百条，整体最多一千条，优先保留活动问题。

服务端新增迁移 `0007_system_notifications.sql`，持久保存共享问题状态及各管理员独立的已读记录。维护任务每分钟观察存储，浏览器每三十秒在可见时同步，重新获得焦点也同步；没有新增设备事件或推送。后续并行功能的迁移编号保持各自独立，不修改既有脚本。

管理 API：`GET /v1/admin/notifications` 返回 `{items, available}`；`POST /v1/admin/notifications/read` 接受 `{items:[{id,revision}]}` 并返回最新名单，最多一百项。返回字段包含内容类型、级别、创建/更新时间、已恢复时间和当前操作者的已读时间。逐次验证已验证邮箱的管理员 HttpOnly 会话及同源请求；写入另验证唯一 Origin、会话 CSRF，并在写事务内复核权限。设备令牌不能访问，不向普通桌面用户提供全站容量或其他账户信息。

桌面通知只在本机原子私有 JSON 中保存，已读不跨设备同步；网络下载记录属于本机，其余传输记录按服务来源和账户隔离。未登录与换号不能看到旧账户记录。下载名单尚未加载时不误报恢复。文件损坏保留原文件并显示不可用，写入失败不能确认已读；状态变更经 Rust 快照实时更新，重新聚焦时自动同步，不可用时每三十秒在可见窗口重试。界面只调用具名 `system_notifications_refresh`、`system_notifications_read`，窗口文件和网络权限不扩大。

## 验证与边界

测试覆盖权限、同源与 CSRF、采样合并、恢复版本、各管理员独立已读、重新打开后的持久化、账户/来源隔离、写入失败、坏文件保留、启动加载顺序、具名桥接、快照样本、弹窗焦点、真实任务定位与中英变量。

实际启动只使用本机隔离数据和预览身份，不创建正式测试账号、不读取真实密码或凭据、不替换用户正在运行的应用。正式服务升级、跨设备与 iOS 验收不由这些本地验证代替。
