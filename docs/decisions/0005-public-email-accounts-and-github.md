# 0005：开放邮箱注册、邮件验证与 GitHub 登录

- 状态：已采纳
- 日期：2026-11-25
- 取代：0002 的账户创建限制、0004 的邀请码注册与仅命令行找回密码部分

## 用户纠正与范围

用户明确纠正：任何人都能注册，不能要求邀请码；登录从用户名和密码改为邮箱和密码，邮箱必须验证；用 SMTP 发事务邮件；改密码和找回密码只在网页，不放进桌面端。同时需要 GitHub 登录与头像。用户选择头像先使用 GitHub 头像和默认头像，不做上传。

0004 曾把邀请码归因为用户已选择的限制，这不能继续作为产品约定。本决定记录这次纠正和原因：用户需要面向所有人的注册入口，不能把运维上的保守默认当作用户授权的注册门槛。

## 后续纠正：正式账号从零开始

2026-11-25 用户在上线后明确要求删除原账号及相关数据，账号部分重新开始。因此正式服务已经清空原账号、网页登录状态、设备授权、云盘与传输、日程与提醒、第三方身份和邮件凭据；不迁移这批旧账号。新账号直接通过公开邮箱注册验证，或通过 GitHub 注册。SMTP、OAuth、配额与本机设置保留；重置前只留受限运维备份，不自动恢复。具体执行证据见[部署手册](../runbooks/deploy.md#2026-11-25按用户要求重置正式账号)。

以下旧账户补绑规则描述保留的兼容实现，不是当前正式新用户的注册步骤。

## 账户规则

- 账户的内部 id 永不随邮箱或 GitHub 名称改变。旧用户名保留为内部兼容字段，普通登录只接受邮箱。
- 注册入口始终存在，不需要邀请码。先向邮箱发送 15 分钟有效的验证凭据，用户确认后才设置密码、创建可用账户。没有验证就没有账户，也不预存别人为这个邮箱填写的密码。
- 邮箱去掉首尾空白、按 ASCII 小写比较；保留点和加号，不做提供商特有的别名合并。格式范围是普通 ASCII 邮箱；不接受显示名、换行或 SMTPUTF8 地址。
- 旧账户在 `/web/legacy` 输入原用户名、原密码和新邮箱，经邮件验证后原地补上邮箱。原 id、设备、云盘与日程保持归属；原密码仍可用于邮箱登录。已有设备凭据不因此失效。
- 更换主邮箱必须先确认原邮箱，再验证新邮箱。只拿到网页会话不能换邮箱。变更完成后撤销原网页登录状态，再建立本次会话；其他设备凭据保留。
- 忘记密码在 `/web/forgot` 经已验证邮箱找回；GitHub 注册的无密码账户也可在这里设置密码。重置后撤销全部网页会话，不自动登录；原设备凭据保留。知道当前密码时仍可在 `/web/account` 改密码。
- 邮箱或密码一旦变更，之前签发的相关邮件凭据失效。消费凭据与改账户在同一数据库事务里完成，过期、重复或并发提交不能覆盖后来的修改。

## GitHub 与主邮箱分开

- 登录身份按 GitHub 返回的稳定数字 id 绑定，不能按可改名的 login 或邮箱认人。
- 首次授权后让用户选择账户主邮箱。`/user/emails` 中标为 verified 的可投递邮箱可以直接使用；填其他邮箱须额外收信验证。GitHub 的 noreply 地址不能作为已验证的可投递邮箱使用。
- **邮箱相同也不自动合并。** 如果邮箱已有账户，用户先登录原账户，输入当前密码，再从账户页绑定 GitHub。绑定流程的 OAuth state、浏览器 Cookie、PKCE、原会话和账户版本必须一致。
- GitHub 另选邮箱、旧账户补绑邮箱与更换邮箱，还需邮件凭据与发起浏览器的 HttpOnly Cookie 配对。仅点击他人发起的验证邮件不能为其创建或绑定身份；在另一个浏览器收信时，把验证码复制回原浏览器的验证页。普通邮箱注册在验信后才由收件人设置密码，不预存发起者的密码。
- 后续 GitHub 登录只按已绑定的 GitHub id 找回原账户；GitHub 主邮箱变化不改 Assemble 主邮箱。GitHub 无密码账户需要通过主邮箱设置密码后，才能使用邮箱密码登录。
- 只申请 `read:user user:email`，不申请仓库权限。OAuth 访问令牌只在 Rust 内存中读取资料，用完释放，不存数据库或设备。
- 未配置完整的 OAuth App 凭据时不展示 GitHub 入口；配置过程见[账户配置手册](../runbooks/email-and-github.md)。

## 头像与界面边界

- GitHub 登录或绑定后使用按 GitHub 数字 id 构造的头像地址，只允许 `https://avatars.githubusercontent.com/u/<数字>?s=96`。
- 邮箱账户默认显示显示名首字；桌面端使用 shadcn Avatar 的 fallback，网络图片失败时保留默认头像。本次不支持上传自定义图片。
- 邮箱与头像是账户公开资料，进入共享协议与桌面状态样本；密码、SMTP 授权码、OAuth Secret、邮件凭据和 Cookie 仍不进入桌面界面。桌面端只增加头像图片来源，不放开任意联网或文件权限。

## 发信与凭据

- SMTP 配置只从受保护环境读取；465 用 TLS 直连，其他选择只允许 STARTTLS，不发送明文授权码。底层错误不回显配置、凭据和邮件正文。
- 密钥支持 `SMTP_PASS_FILE`、`GITHUB_CLIENT_SECRET_FILE` 引用受保护文件，由 Rust 直接读取；环境明文与文件引用不能同时配置。这样本机 Shell 和启动参数不必载入密钥。
- 账户绑定 GitHub 的表单安全策略只额外放行固定的 `https://github.com`；否则浏览器会拦下提交后到提供商的跳转。其他跨站表单仍被拒绝。
- 邮件凭据随机生成，只存摘要，15 分钟内单次有效。邮件链接把凭据放在 URL 片段中，不进入 HTTP 查询串、代理访问日志或 Referer；验证页的一小段本站脚本只负责填表并清掉片段。禁用脚本时可从邮件复制验证码。
- GET 不消费凭据，用户必须提交本站 CSRF 表单。邮件扫描器单纯打开链接不会注册账户或改密码。
- 发信按数据库预留限额：每邮箱每分钟一次、每小时五次，整个服务每小时最多 120 封。重启和并发不能绕过，限额键只存摘要。注册和找回请求的对外结果不透露账号是否存在。
- GitHub 的回调由提供商携带单次 code，代理必须关闭该路径的访问日志；示例配置已包含这一点。应用不记录回调 URL、令牌或 SMTP 诊断原文。
