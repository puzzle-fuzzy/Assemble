# 决策 0008：共享与私人影视片库及展示站

- 状态：已采用；2026-11-25 正式部署并核对真实来源，2026-11-26 完成授权的 Jarvis 线上影视导入与校验；管理维护及跨设备的真人操作仍待本人验收
- 日期：2026-11-25

2026-11-27 用户重新确认跨端边界：管理端管理所有用户影视，桌面端维护本人片库，全站网页展示各用户公开内容，个人网页只展示对应用户公开片库。公开策略明确选为“默认私有，主动公开”。下面的规则已按这次确认更新；新增发布边界目前仅完成源码与本地验证，尚未部署，不代表正式环境已经改变。

## 原因与用户确认

用户要求参考只读的 `jarvis` 仓库，将影视管理、桌面列表与详情接入 Assemble，并新增面向浏览者的海报墙。随后明确：共享片库由管理员维护，每个账户另有仅本人可访问的私人片库；两种片库都支持想看、在看、已看。不能沿用 Jarvis 共享库只有两种状态的限制。

共享内容继续允许匿名浏览，磁力链接需要登录；用户片库默认私有，由本人逐条明确选择公开。管理端仍然只在网页中使用，新增对所有用户片库的查看和维护，保留真实归属与操作审计。桌面端只维护本人片库，不因账户具有管理员角色而获得他人或共享库写入入口。影视扩展不改变其他业务的管理权限。

Assemble 使用自己的服务端与账号。最初仅授权只读参考与复用 TMDB 凭据；2026-11-26 用户进一步明确要求从 Jarvis 线上完整获取影视数据，包括缓存和封面，因此增加显式维护导入。只迁移影视业务、图片和旧影视归档，不迁移账号、任务的认证会话关联、旧站点或域名配置。源库、源文件与参考仓库保持只读，密钥仍只能进入受保护服务端配置。

## 决定

### 归属、状态与可见性

| 内容                                 | 读取                                           | 维护                                       |
| ------------------------------------ | ---------------------------------------------- | ------------------------------------------ |
| 共享条目、共享观后感、共享图集与合集 | 匿名可读                                       | 已验证邮箱的超级管理员，只经网页管理 API   |
| 共享磁力链接                         | 登录后可读，匿名只返回是否存在                 | 同共享条目                                 |
| 共享备注                             | 仅超级管理员可读                               | 同共享条目                                 |
| 未公开的用户条目、图片、观后感与磁力 | 所属账户及同源网页超级管理员                   | 所属账户，或网页超级管理员；保留归属与审计 |
| 主动公开的用户条目、图片与观后感     | 匿名可读；磁力仍需登录                         | 同上，撤销公开后立即恢复私有读取           |
| 用户备注                             | 所属账户及同源网页超级管理员；公开投影始终剔除 | 同上                                       |
| 统计                                 | 仅超级管理员                                   | 包含共享库及所有用户片库，不对外公开       |

两种归属都使用 `planned`、`watching`、`completed`。来源身份在所属范围内去重，不能因共享库已存在同一作品就公开私人记录。公开不改变 `scope=private` 或所有者，使用独立的 `published` 标记；本人未主动勾选并保存前不公开。已有私人记录升级默认不公开，缺少新字段的旧输入默认私有。现有 147 条共享影视及 16 个合集保持共享归属，不删除或强制移入某个账户。合集继续只引用共享条目，不把已发布的用户记录当作共享成员接纳。猜测未公开的他人标识按不可访问处理。

“主动公开”只由所有者本人决定。服务端在更新事务内按已加载的所有者与真实操作者检查：私人记录从未公开变成公开，只有所有者本人可执行；管理员可以维护他人资料、保留既有公开选择或撤下，但不能代为首次公开，也不能把已撤下的记录重新公开。管理员自己的私人记录按本人规则处理，共享库维护不受此限制。编辑页明确传入当前账户标识，禁用代公开选项；他人此前已公开的记录仍可在保存前取消或恢复原选择。

### 三个界面共用一套业务展示

- `apps/admin` 同源 `/admin/`：全部片库列表、归属和可见性、按用户名称/ID 与片名查询、共享和用户记录维护、来源搜索导入、真实任务进度、图集和封面、共享合集与全用户统计。所有读取逐次检查网页超级管理员和同源，写入还检查 CSRF；设备令牌不能替代网页管理会话。管理跨用户操作不冒用目标账户，操作者、目标归属及记录 ID 在同一事务内审计，不记录备注或磁力原文。
- `apps/desktop`：直接维护本人片库的列表与详情、来源导入、图集及逐条发布/撤销；全站浏览跳到固定的第一方网页入口。只经 Rust 具名命令访问服务端，图片经受控资产读取并核对长度与摘要后返回图片数据；复制磁力时重新授权。不放宽通用联网、剪贴板或文件路径能力。
- `apps/media-web` 同源 `/movies/`：全站海报首页展示共享记录和各用户主动公开的记录；`/movies/users/{accountId}` 仅展示该用户主动公开的记录，不用邮箱作公开标识。登录本人仍可经 `/movies/private` 只读查看自己的全部记录。三种观看状态、类型切换和分页沿用同一逻辑，个人主页的筛选和返回详情保留归属。公开详情永远不包含备注，磁力仍需登录。登录跳到第一方服务端网页；站点不处理密码、不保存设备令牌、不提供维护入口。

ToC 是本仓库提供、由服务端托管的固定第一方程序，不是任意用户上传网页的静态托管入口。它复用已有来源、HttpOnly 网页会话与外观偏好，不切换 Jarvis 旧站点，也不新增另一套账号。

影视 DTO、浏览器适配、业务组合与 `media` 中英字典放在 `packages/media`；Rust 类型仍以 `assemble-protocol` 为准，并用两侧共读样本约束。三端共用 `packages/ui` 的 shadcn、Lucide、主题与字体，国际化复用 `packages/display` 单例。ToC 的站点文案使用独立 `mediaSite` 命名空间；默认简体中文、跟随系统。同源管理站与展示站共用当前浏览器的偏好，不承诺跨设备同步。

### 来源、任务与图片

服务端负责 TMDB、豆瓣请求；只访问固定 HTTPS 来源，不读取用户 Cookie、不跟随任意重定向。TMDB 使用受保护的 `ASSEMBLE_TMDB_TOKEN` 或 `ASSEMBLE_TMDB_TOKEN_FILE`，两者不能同时设置。豆瓣公开接口遇到限制时返回稳定来源错误，不绕过验证；能力标记不等于真实网络已经可用。

导入与图集同步使用持久任务，阶段为资料、图片、保存；只有服务器确认的项目数量才显示进度，未知时不制造总体百分比。未知提交结果的重试沿用 requestId，已失败或中断后用户明确重新尝试使用新 requestId。编辑与封面选择携带版本，冲突不覆盖已有资料；界面保留草稿，用户明确重载才替换。

图片只接受受限 JPEG、PNG、WebP，校验大小、尺寸、像素与摘要后，原图和缩略图一并在事务内发布。匿名资产读取必须有当前有效的共享或主动公开记录引用，或已有的独立公开来源缓存/导入引用；资产存在本身不授予读取权限。每次详情、图集及图片请求重新核对公开状态，不缓存私人投影；撤销公开立即取消该条目的公开引用。只有经同源校验的管理访问可扩展到所有用户图片。演员来源页面只含独立公开来源资料，不查询或推断用户私有记录；私人任务只给所属账户和同源网页管理员读取，不因条目公开而公开任务。磁力只存储和复制，服务端不运行 BT 下载。

### 存储与部署

新增 `apps/server/migrations/0005_media.sql`，不修改已提交的 0001～0004。影视条目、身份关联、任务、合集与图片资产均进入 SQLite，图片原图和衍生版本为 `media_asset_variants.content` BLOB。备份与恢复必须包含数据库中的图片，不能只拷贝现有 `blobs/` 文件目录；私人内容按敏感数据保管。

`0012_media_publication.sql` 增加公开检索索引并补全旧记录的发布状态和归属投影：共享保持公开，私人默认不公开；不修改原有迁移和归属列。发布/撤销沿用带版本的更新命令，与内容保存原子提交，旧版本不能覆盖当前选择，图集任务也不能用过期版本重新发布内容。

展示资源由 `ASSEMBLE_MEDIA_WEB_ASSETS_DIR` 指定，本地默认 `apps/media-web/dist`，镜像内为 `/usr/share/assemble/movies`。镜像一起构建管理端和展示站，升级仍按既有部署手册传送镜像，不修改共用 nginx 的其他站点。迁移只向前；回滚需要同时恢复升级前完整数据和对应镜像。

## 验证与当前状态

2026-11-26 用户指出 ToC 原界面与 Jarvis 的浏览体验不符：不需要顶部 header、复杂筛选及重复说明。源码因此改为类型切换与“想看 / 在看 / 近日观影”海报分区，保留 Assemble 的三个状态。取消可见的搜索、年份、题材、状态和排序表单；不缩减管理端或底层查询 API。三个分区分别分页，详情返回保留类型与页码；空分区隐藏，整库为空只保留一条文字。只读详情使用共享业务组件的 reader 呈现，隐藏空观后感、空演员、空图集及未知日期，来源改为可打开的链接。私人读取、磁力登录和复制前重新授权均沿用既有规则。这次界面调整的本地证据及发布状态见影视手册。

代码已经具备条目增删改查、真实来源适配与导入任务、图集、封面、演员作品、合集、统计和三端接线。界面回归已覆盖版本冲突、401 清除旧内容、账户切换取消旧请求、任务续看与幂等、封面选择和合集中成员顺序；这些显式测试夹具不代表真实来源成功。

本地完整验证、隔离真实来源、Chrome 和 Windows 原生预览、Docker 构建与启动已经完成，分别记录在[影视手册](../runbooks/media.md)。Windows 普通窗口中的筛选区按内容容器宽度收紧，避免列表被挤出首屏；三端不为此增加第二套控件。部署前主机直连 TMDB 超时，用户决定先发布；正式容器启用后，两个来源的实际公网资料和海报请求均已通过，未新增代理。2026-11-25 已发布服务端与两个网页，桌面安装包已单独构建，尚未替换运行中的安装版。实施范围见[计划](../plans/2026-11-25-media-library.md)。
