# 0004：邀请码注册，以及在网页上改密码

- 状态：已采纳（注册方式与第一个账户的密码是 2026-11-25 你定的；其余细节是我采用的默认，你没有逐条确认）
- 日期：2026-11-25
- 依据：[决策 0002](0002-own-server-replaces-jarvis.md) 把账户定为"服务器命令行创建，不开放注册"；本决定把后半句改掉。

## 背景

2026-11-25 你在一台 Windows 电脑上第一次登录正式服务，卡在了登录页。你的原话：

> 也不是说管理端吧，就是我需要一个账号，但是现在我们的 https://as.yxswy.com/web/login?next=… 页面也没有对应的注册入口什么的，你可以先给我一个账号密码，然后再把注册给加上吗

两件事：眼下要一个账户；以后要能注册。

## 决定

| 事项             | 决定                                                                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 注册方式         | **邀请码注册。** 服务器上配一个邀请码，注册页上填对它才能建账户；没配邀请码，就没有注册页。你从"默认关闭、需要时打开"和"完全开放"里选了这一种                                          |
| 第一个账户的密码 | **一次性的例外。** 你让我建账户，并把密码直接发在对话里。我提醒过它与"密码不经过助手"的规矩冲突、密码会留在会话记录里，你仍然选了这一种。规矩本身不变（见[协作约定](../../AGENTS.md)） |

## 怎么做的

- **邀请码只放在服务端的配置里。** `ASSEMBLE_INVITE_CODE`，8 到 128 个字符，不能有空白。读完配置只留它的摘要：进程里、日志里、这份配置的调试输出里都没有邀请码本身；比对的时候把用户填的也算一遍摘要再比。
- **注册页和登录页是同一套防线。** 写操作必须来自本站；表单带一个与 Cookie 成对的随机值；填错时页面上只摆回用户名与显示名，不摆密码与邀请码，回答里只有一句"邀请码不对"。
- **邀请码连续错太多次，暂时不接受任何人的注册。** 与登录失败共用一张表：15 分钟内错 5 次就挡。服务端看到的请求都来自反向代理，分不出来源，所以这个次数按全局计——会用注册页的只有被邀请的那几个人，挡一阵子的代价很小。
- **注册成功就算登录**，直接回到原来要去的页面（通常正是桌面端的授权确认页）。
- **登录之后有一个账户页** `https://<服务地址>/web/account`：改密码、退出登录。改密码要输现在的密码；改好之后，这个账户在别处的网页登录状态全部作废，只留下正在用的这一次。电脑与助手上的 Assemble 用的是各自的设备凭据，不受影响。
- **命令行上可以给账户换密码**：`assemble-server set-password <用户名>`，忘了密码的时候用。它不核对旧的密码，所以只能从服务器上做；做完之后这个账户的网页登录状态全部作废。

## 没有选的两种，以及原因

- **默认关闭、需要时打开。** 最稳，但每注册一个账户都要动一次服务器；你自己换设备、或者想叫别人用的时候，多一道手续。
- **完全开放。** 任何人在公网上都能在这台服务器上建账户，用它的磁盘和流量。它只有 2 核 2 GB，还和别的站点共用。

## 我采用的默认，你没有逐条确认

- 邀请码的长度与字符规则（8 到 128 个字符，不能有空白）。
- 邀请码连错 5 次挡 15 分钟，而且是全局的。
- 改密码只让别处的**网页**登录状态作废，不把电脑与助手上的 Assemble 踢下线：否则改一次密码，每台电脑都要重新登录一次。想收回某台电脑的登录，在桌面应用的"设备"卡片里移除它。
- 加了 `set-password` 这个命令。你没有要它；但有了改密码而没有找回，忘了密码就只能重建一个账户，日程和文件都留在旧账户里。

## 后果与还没做的

- 正式服务的 `.env` 里从此有一份要保管的东西：邀请码是明文，服务器上的 root 看得到。以前那份文件里没有秘密。
- 注册出来的账户没有角色之分，和第一个账户一样。
- 没有"忘记密码"的邮件找回：只能从服务器上用 `set-password`。
- 邀请码目前只有服务器上配的那一个，不能在网页上生成或作废单个邀请。
