# 0013：DHT 功能迁入 Assemble，先只供管理端使用

- 日期：2026-11-26
- 状态：已采用

用户要求迁入 `E:\dht-observer` 与 `E:\dht-spider` 的功能，页面沿用 Assemble 现有形式，先做管理端，暂不放到用户端。随后明确选择：先迁移功能，历史数据暂不导入。

## 决定

- 协议和元数据边界放在 `assemble-dht`，SQLite 队列、生命周期和 HTTP 适配放在 `apps/server/src/dht`。保持 Rust 服务端，不运行旧 Node 服务、旧 Spider 进程或独立数据库。
- 迁移被动 announce、BEP-51 采样、BEP-9/10 元数据解析、有界可选 PEX、查询与筛选、文件清单、磁力复制、按哈希主动查询、自动刷新和聚合诊断。旧站独立密钥与会话管理由 Assemble 现有网页管理员会话取代。
- `/admin/#dht` 复用 sidebar-13、共享表格、详情对话框、主题、字体和中英字典。筛选位于对应表头，后台刷新保留当前行与焦点。没有桌面、普通用户网页或 MCP 的 DHT 入口。
- `/v1/admin/dht/*` 每次检查浏览器会话、已验证邮箱、超级管理员与同源；写入另外验证 CSRF。设备令牌无权限，响应不缓存。
- 只观察与保存哈希、时间、来源次数、校验后的名称、大小和文件清单，不下载内容文件。原始 info 字节经过 SHA-1、bencode、分片长度、总大小及路径检查后才能发布；节点和 Peer 地址只留在有界运行内存中。
- 明确区分采集、排空和停止。排空停止新观测与采样，继续处理已有队列；停止取消全部网络任务。运行模式持久化，重启后恢复模式；被中断的解析恢复为待处理，尝试次数不重置。
- 默认不启用采集，启用配置后仍需管理员点击“开始采集”。默认 UDP 6882，避免与旧服务的 6881 冲突；生产端口、安全组与旧实例的处置另行确认，不在功能迁移中执行。
- 使用新迁移 `0008_dht.sql`，不改已有迁移、不导入旧数据、不复制旧站凭据、不停止旧服务。记录、队列、解析并发和文件清单存储都有预算，达到上限如实报告。

## 实现差异

旧 Observer 的 Node/native/hybrid 解析器及生产 canary 脚本不作为新服务的运行依赖；Assemble 使用一套 Rust wire 解析器。诊断提供持久化状态与本次进程的查询、成功、超时、连接、协议、校验和落盘计数，不宣称兼容旧站每个试验参数或诊断矩阵。采集并发不因失败次数自动提高。

边界、配置与验证方式见 [DHT 手册](../runbooks/dht.md)。来源与 MIT 许可证记录在 [协议库](../../crates/assemble-dht/PROVENANCE.md)。
