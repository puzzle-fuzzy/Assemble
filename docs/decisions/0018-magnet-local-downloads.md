# 决策 0018：本机磁力下载与持久续传

- 日期：2026-11-27
- 状态：已采用；验证与安装范围见网络下载手册

## 用户要求

用户明确要求将磁力链集成到现有网络文件下载，支持文件选择、暂停续传和重启恢复；上传策略选择“下载期间限速上传，完成即停”。因此下载按钮旁明确说明上传上限和停止时机，不启用完成后做种。

## 决定

嵌入稳定版 Rust `librqbit 9.1.0`（Apache-2.0），不要求安装外部 BT 程序，不将任务转到服务端。首版支持有 v1 信息哈希的公开磁力，拒绝私有种子与纯 v2。先从真实节点获取元数据，再展示文件标识、相对文件名与大小，必须明确选择至少一个文件。

每个任务上传上限 256 KiB/秒，与视频下载共用两个执行名额。完成分片后先停止 BT 会话，再校验并发布文件；暂停、取消、正常退出等待会话停止。应用重启不自动联网，未完成任务恢复为暂停；点击继续会重新逐片校验，不把旧进度当作可信缓存。取消删除本任务缓存和来源凭据，已经发布的文件保留。

缓存使用 `.assemble-magnet-<任务标识>`，与视频的崩溃暂存清理分开。目标目录只来自系统默认目录或选择器。引擎仅写私有缓存；完成后对所选文件计算 SHA-256，用已校验的副本和原子硬链接发布到独占的新目录。同名保留双方。拒绝越界路径、符号链接、Windows 保留名及冲突文件名；保留原格式，空文件也可发布，不经 FFmpeg。

可重放的磁力与 Tracker 参数只存在 Rust 和系统钥匙串。为适应 Windows 单项凭据容量，按 UTF-8 边界拆为最多 16 项，每项不超过 1024 字节。私有任务历史仅存去掉 Tracker 等外层字段的原始 `info` 元数据、选择项、进度与内部落盘位置；恢复前对照钥匙串来源核验信息哈希。引擎关闭自己的持久化与局域网发现，不开启 BT 入站监听、UPnP 或 HTTP 控制服务。桌面日志在 trace 级别也过滤引擎的诊断，避免原始网址被第三方依赖记录。

限额：元数据 4 MiB、10,000 文件、种子总大小 1 TiB、单任务所选内容 100 GiB、每任务 64 节点；Tracker 最多 16 个，显式节点最多 32 个。开始及执行前检查剩余空间，考虑缓存与发布副本同时存在的容量。任务历史最多 100 条，未完成磁力任务占用队列名额。

协议、桌面具名命令和 MCP 一起扩展。助手仍通过已认证的本机通道，只能操作自己发起的任务；开始命令带文件标识，幂等参数包含文件选择。新增暂停、继续、取消三个工具，不接受本机路径。影视片库的“复制磁力”入口保持原功能。

## 验证边界

默认 Rust 测试使用回环地址的真实 BT 种子交换元数据与分片，核对选择文件、空文件、暂停、恢复、损坏分片重下、同名保留、缓存清理和凭据投影；另测中断历史、取消解析、路径/链接与所选容量。真实应用启动和 Windows 真机结果单独记录，不用规则测试替代。

跨平台路径以种子中逐段解码的名称生成统一的斜杠形式，再交给各系统路径边界校验；不把 Windows `PathBuf` 的反斜杠当作来源字符。真实 BT 回归包含中文子目录，确保文件选择和重启恢复保留同一组相对名称。
