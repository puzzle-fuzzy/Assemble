# 0006：只读管理端与共享 shadcn 界面

- 日期：2026-11-25
- 状态：已采用
- 取代：0002 中暂不做管理端的范围限制；桌面端原单内容栏布局

## 用户反馈与范围

用户要求先补齐超级管理员页面，查看注册用户、登录时间和设备；管理端参考官方 `sidebar-13`，桌面端参考 `sidebar-09`，两端共用同一套 shadcn 组件。用户随后确认：本次只完成管理端与现有功能布局，定时邮件、RSS 不在本次实现范围内。

初版三列部署后，用户在桌面会话明确纠正：桌面也改成与管理端一样的 `sidebar-13`，忽略之前仅显示图标的规则。最终布局为左侧图标加文字菜单、右侧整页内容，不再保留中间项目栏。原三列实现与验收仅作为历史记录。

随后用户指出菜单间距与图标观感未对准官网，并要求版本、官网移入侧栏“关于软件”，桌面及管理端的内容区不再重复面包屑已有的页面标题。官网实际预览使用 New York sidebar-13：菜单行间距 4px、按钮高 32px、图标 16px、图文间距 8px。项目此前 Nova SidebarMenu 的行间距为 0；现在在共享组件中统一为官网尺度，不改现有主题或字体。可见页面标题由面包屑承担，键盘导航焦点也移到面包屑；业务分组标题和表单标题保留。

用户随后提供 sidebar-08 的底部账户区参考图，要求桌面账户中心与管理端右上头像统一放到侧栏菜单下方。当前使用共享的底部头像、姓名和邮箱触发器，弹出实际账户操作；普通菜单不再重复账户中心。此轮用户要求先部署供查看，确认后再提交，部署预览不能冒充已提交版本。

用户随后要求桌面侧栏“关于软件”移到左下角用户菜单并改名“关于”，将版本和官网信息与账户操作集中，普通功能区只保留业务入口。“关于”在未登录及断网时也可打开；选择后与其他页面一样把焦点移到面包屑，关闭菜单则回到原触发器。

用户同时确定桌面与管理端的文案原则：避免不必要的次级标签和说明，让布局表达用途。移除重复页面用途、指标释义及显然的空态提示；搜索保留具名但不重复显示标签。账户状态、容量、错误恢复和操作风险仍保留，时区通过时间与今日指标的提示提供。

用户随后指出发送面板的文件摘要与发送去向使用相同的边框行，容易把只读信息误认为操作入口。现在文件以无边框的图标、名称和大小列表展示，长文件名换行；分隔线下的实际按钮直接写“上传到云盘”或“发送到设备”，配合箭头表明点击后的动作，不再附加“存到服务端”的重复说明。离线禁用、发送中防重复、进度、失败重发和成功后收起的行为保持不变；键盘跳过文件摘要，直接到达可操作入口。

2026-11-25 用户再次明确：管理端只能是网页，不存在管理端桌面程序。本地开发预览与正式使用方式必须区分清楚；共用组件仅为保持界面一致，不能据此把管理功能做进桌面客户端。

依照这次纠正，管理登录入口明确显示管理控制台身份；登录、找回密码后的重新登录及退出都保留浏览器内的管理入口。管理退出后不再显示“可以关闭此页面”的设备式提示，而是返回管理登录页。正式管理员仅访问网页，不需要在自己电脑上运行开发服务。

## 决定

- 管理端是 `apps/admin`，只在浏览器中使用，由 Rust 服务端在同一来源的 `/admin/` 发布，不提供 Tauri/Electron 管理端或嵌入桌面客户端的管理页面。保留 sidebar-13 内部的左侧菜单、页头与内容关系，移出官方示例的 SettingsDialog，成为完整页面。提供概览、用户、设备与登录记录；支持查询、分页和用户详情，不提供账号删除、封禁或任意提权操作。
- 桌面端与管理端统一 sidebar-13 的两栏结构，文字菜单切换已有传输、云盘、日程与提醒、本机设置。两端侧栏底部的账户区沿用 sidebar-08：桌面从弹出菜单进入“账户中心”“关于”或退出，管理端从这里退出，不保留右上头像。搜索位于对应整页内容内；窄窗口使用共享菜单组件保留对应入口。保留日程草稿、托盘与通知定位，版本与官网仅在关于页展示，不在主窗口底部重复显示。
- 基础组件、主题和字体只有一份实现，位于 `packages/ui`。旧桌面组件路径仅转发导出，应用只组合这些组件；缺少的基础组件使用 shadcn CLI 获取，不另写一套控件。
- 管理 API 复用浏览器 HttpOnly 会话，每次核验邮箱已验证且有管理员权限，并检查同源读取。设备令牌不能访问管理 API，管理页面不接触密码、会话 Cookie、SMTP 或 OAuth 密钥。静态壳公开可读，账户数据只经受保护 API 获取。
- 管理员由服务器受保护的 `ASSEMBLE_SUPER_ADMIN_EMAIL` 指定：仅对匹配的已验证邮箱授予权限并写审计。不会把第一个注册者变成管理员。用户指定的真实邮箱只放在部署配置中。也可通过服务器 CLI 为已有已验证邮箱授权，没有公开提权接口。

用户随后明确两个邮箱并列为超级管理员。已验证的账户通过服务器 CLI 授权并审计；尚未注册的另一个邮箱保留受保护 bootstrap 配置，完成验证后获得同等权限。不创建占位账户，不按 GitHub 邮箱自动合并身份。

- 新增迁移 `0004_admin.sql`，不修改已提交迁移。成功创建网页会话时同事务记录登录时间、邮箱/GitHub 登录方式；失败登录、普通页面访问和设备活跃不冒充登录。历史未知时间保持空值，管理端显示“未记录”。

## 后果与验收

服务端镜像需要同时构建管理前端。`bun run verify` 检查两端与共享包，并构建两个前端；部署时一并发布静态资源与 Rust 二进制。管理员必须本人注册、验证并登录，助手不替本人输入密码，也不在正式环境创建测试账号。权限测试、本地真实启动和本人正式使用分别报告，不能互相替代。

具体配置与核对步骤见[管理端手册](../runbooks/admin.md)。

## 2026-11-26：表格统一为 dashboard-01

用户指定 [shadcn dashboard-01](https://ui.shadcn.com/blocks) 首页的数据表格为全项目标准。共享表格组合放在 `packages/ui`，复用官方区块的圆角细边框、灰底固定表头、平铺行、列显示菜单、勾选、行操作菜单，以及每页条数、页码和四个翻页按钮。用户、设备、登录记录与桌面和管理端的影视列表使用同一实现，主题和字体继续共用；影视站的海报墙仍按海报展示。

读取远程列表继续使用已有服务端搜索和分页，不为表格拉取整个账户的数据，也不在单页数据上再次分页。详情中的少量设备和登录记录才在本机分页。勾选只属于当前数据页，换页或更换结果集会清空；列显示只保存在当前组件内，不改变账户或业务数据。行菜单只连接已有权限允许的实际操作，不添加无业务支持的拖拽或占位按钮。

用户同时要求影视列表去掉重复的片库标题和说明，筛选只保留关键词、作品类型、观看状态。根据随后对截图的纠正，类型与状态筛选直接放在对应表头，用共享 shadcn DropdownMenu 单选菜单选择；搜索框仅显示占位文字，隐藏标签仍提供无障碍名称。清空筛选使用搜索框末尾的图标按钮，一次重置三个条件、回到第一页、保留每页条数，并将焦点交回输入框。表格无数据时仅显示文字，不显示空态图标。移除年份、类型标签及排序输入；默认仍按最近更新排列。两种语言完整维护，Dialog 标题和表格说明保留必要的无障碍语义，窄区域通过具名、可聚焦的表格滚动区保持列关系。
