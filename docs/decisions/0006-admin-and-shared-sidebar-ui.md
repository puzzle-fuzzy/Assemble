# 0006：只读管理端与共享 shadcn 界面

- 日期：2026-11-25
- 状态：已采用
- 取代：0002 中暂不做管理端的范围限制；桌面端原单内容栏布局

## 用户反馈与范围

用户要求先补齐超级管理员页面，查看注册用户、登录时间和设备；管理端参考官方 `sidebar-13`，桌面端参考 `sidebar-09`，两端共用同一套 shadcn 组件。用户随后确认：本次只完成管理端与现有功能布局，定时邮件、RSS 不在本次实现范围内。

## 决定

- 管理端是 `apps/admin`，由 Rust 服务端在同一来源的 `/admin/` 发布。保留 sidebar-13 内部的左侧菜单、页头与内容关系，移出官方示例的 SettingsDialog，成为完整页面。提供概览、用户、设备与登录记录；支持查询、分页和用户详情，不提供账号删除、封禁或任意提权操作。
- 桌面端保留 sidebar-09 的三列：图标导航、可搜索的项目列表、所选内容。接入已有传输、云盘、日程与提醒、本机设置；账户与设备面板仍由左下头像打开。保留日程草稿、托盘与通知定位、版本及官网展示。
- 基础组件、主题和字体只有一份实现，位于 `packages/ui`。旧桌面组件路径仅转发导出，应用只组合这些组件；缺少的基础组件使用 shadcn CLI 获取，不另写一套控件。
- 管理 API 复用浏览器 HttpOnly 会话，每次核验邮箱已验证且有管理员权限，并检查同源读取。设备令牌不能访问管理 API，管理页面不接触密码、会话 Cookie、SMTP 或 OAuth 密钥。静态壳公开可读，账户数据只经受保护 API 获取。
- 管理员由服务器受保护的 `ASSEMBLE_SUPER_ADMIN_EMAIL` 指定：仅对匹配的已验证邮箱授予权限并写审计。不会把第一个注册者变成管理员。用户指定的真实邮箱只放在部署配置中。也可通过服务器 CLI 为已有已验证邮箱授权，没有公开提权接口。
- 新增迁移 `0004_admin.sql`，不修改已提交迁移。成功创建网页会话时同事务记录登录时间、邮箱/GitHub 登录方式；失败登录、普通页面访问和设备活跃不冒充登录。历史未知时间保持空值，管理端显示“未记录”。

## 后果与验收

服务端镜像需要同时构建管理前端。`bun run verify` 检查两端与共享包，并构建两个前端；部署时一并发布静态资源与 Rust 二进制。管理员必须本人注册、验证并登录，助手不替本人输入密码，也不在正式环境创建测试账号。权限测试、本地真实启动和本人正式使用分别报告，不能互相替代。

具体配置与核对步骤见[管理端手册](../runbooks/admin.md)。
