# 0017：同账户远程桌面第一批

- 日期：2026-11-27
- 状态：已实现源码，尚未发布与双机验收
- 来源：用户要求开始制作远程功能，并明确 `E:\desk-link` 已经能正确实现基础远程，可参照它的功能。

## 范围与参考

沿用 Assemble 自有服务端、同账户设备和 Rust/Tauri 边界，不依赖 DeskLink 的账户、中继或安装。DeskLink 源仓库只读；参考其先批准再采集、归一化坐标、有界队列和显式释放输入，未直接引入其含有 unsafe 的平台实现。

本批支持 Windows/macOS 双向作为控制端与被控端：请求、明确允许/拒绝、画面、鼠标/拖动/滚轮、常用键与组合键、Unicode 文字、显示器切换、原生全屏、双方结束。发送文件复用现有发送面板，保存与校验规则不变。

## 实现

- `assemble-protocol::remote` 是唯一线上类型；`assemble-client::remote` 访问固定来源，不跟随重定向。
- `assemble-remote` 的纯输入规则独立于网络和窗口；可选 `native` 使用稳定版 xcap 0.9.10、enigo 0.6.1 和已有 image。平台依赖的 unsafe 不进入工作区源码。版本已由 crates.io 核对稳定版。
- 服务端复用已有设备令牌逐次认证，只允许同账户的两个不同 Windows/Mac 设备，每台电脑同时只参加一场。没有新的账号、公开端口、数据库结构或远程密码。
- 请求 60 秒过期。只有被控端能批准，桌面主窗口的具名命令启动本机线程。批准之前不采集、不注入输入；服务端返回 active 也不能自行启动本机采集。
- 画面使用 HTTPS 中转的独立 JPEG，最长边不超过 1600×1000 的边界，必要时降到 1000×700，压缩后最多 512 KiB。发送后至少等待 100 毫秒；请求和编码耗时会降低实际帧率。它是基础画面链路，不宣称达到 DeskLink 的 H.264/30 FPS。
- 内存仅保留最新一帧。输入最多 128 项，一批最多 32 项，单调序号、重试去重、接收方确认后清除；溢出直接结束会话。浏览器输入同样限制队列，一个在途请求，移动事件合并。
- 双方通过轮询续期，超过 5 秒未续期即结束；服务端重启后全部会话失效。客户端网络错误停止会话，重新连接需要重新批准，不自动恢复控制。
- 本机停止、失焦、页面卸载、账户更替、输入失败、显示器切换与退出都释放已按下的键鼠。关闭主窗口结束远程会话，新的被控请求会叫出主窗口。Esc 始终释放本机键盘焦点，工具栏另可向远端发送 Esc。退出时显式等待工作线程，远程会话阻止空闲自动更新重启。输入库的日志在全局日志入口强制过滤，即使启用 trace 也不能记录键入文字。
- 画面与输入经 TLS 保护，但当前不是端到端加密：Assemble 服务端是受信任中转，可见业务内容。内容不入库、不记录日志、不做录像；审计只记录申请、批准和结束的会话标识。端到端密钥、硬件视频、音频、剪贴板自动同步、直连、无人值守与手机控制留待后续方案。
- 助手只获得 `assemble_remote_devices`，列出当前账户的 Windows/Mac 设备。连接、批准、屏幕与输入不开放给助手。

## 验证边界

服务端真实 HTTP 测试覆盖批准、方向限制、账户/设备隔离、输入确认与重试、撤销、拒绝与关闭清空画面。React 测试覆盖具名桥接、输入合并、StrictMode、语言切换与批准前失焦。两侧继续读取同一份桌面快照样本。

本机 Windows 原生探针实际采集过两个显示器中的主屏，输出 1600×900、176312 个 base64 字节，只报告尺寸，不保存画面、不移动鼠标或键入。它不替代双机传输、真实键鼠与 Mac 权限验收。最新完整验证、真实启动和上线状态见[远程手册](../runbooks/remote.md)。
