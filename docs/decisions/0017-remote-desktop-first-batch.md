- 状态：已实现源码，尚未发布与双机验收
- 来源：用户要求开始制作远程功能，并明确 `E:\desk-link` 已经能正确实现基础远程，可参照它的功能。
- 范围确认：2026-11-27 用户选择“保留现有边界，补齐其余远控能力”，因此仍是同账户、逐次批准、自有服务端中转，不引入跨账户、直连或可信设备免确认重连。

## 范围与参考

沿用 Assemble 自有服务端、同账户设备和 Rust/Tauri 边界，不依赖 DeskLink 的账户、中继或安装。DeskLink 源仓库只读；参考其先批准再采集、归一化坐标、有界队列和显式释放输入，未直接引入其含有 unsafe 的平台实现。

本批支持 Windows/macOS 双向作为控制端与被控端：请求、核对代码、明确允许/拒绝、画面、鼠标/拖动/滚轮、常用键与组合键、Unicode 文字、双向纯文本剪贴板、系统声音、画质选择、显示器切换、适应/1:1 拖动浏览、原生全屏、光标位置及双方结束。发送文件复用现有发送面板，保存与校验规则不变。

## 实现

- `assemble-protocol::remote` 是唯一线上类型；`assemble-client::remote` 访问固定来源，不跟随重定向。
- `assemble-remote` 的输入规则与有界原生工作线程独立于网络和窗口；平台对象在工作线程内创建，不要求它们能跨线程移动。可选 `native` 使用稳定版 xcap 0.9.10、enigo 0.6.1 和已有 image。平台依赖的 unsafe 不进入工作区源码。版本已由 crates.io 核对稳定版。
- 服务端复用已有设备令牌逐次认证，只允许同账户的两个不同 Windows/Mac 设备，每台电脑同时只参加一场。没有新的账号、公开端口、数据库结构或远程密码。
- 请求 60 秒过期。只有被控端能批准，桌面主窗口的具名命令启动本机线程。批准之前不采集、不注入输入；服务端返回 active 也不能自行启动本机采集。
- 原生软件 OpenH264 编码，浏览器 WebCodecs 解码；无法编码或解码时回退 JPEG。自动、流畅、均衡、清晰对应有迟滞的实际采集策略，最大边界分别为 1000×700、1600×1000、1920×1200；JPEG 每张最多 512 KiB，超限再缩小。H.264 目标 30 FPS，实际速度取决于采集、软件编码和中转，未承诺硬件编码或达到 30 FPS。流切换、丢帧、积压会重置解码链并请求关键帧；单场保留最多 8 个视频密文帧，另有字节上限和全局预算。静止 JPEG 跳过上传，光标位置通过独立加密心跳更新。
- 2026-11-27 继续完善时，修正首版串行采集/上传拖慢键鼠的问题：`assemble-client::remote_host` 独立驱动输入和画面，各自只有一个在途请求。输入轮询后至少等待 50 毫秒，原生队列最多两项；它可能等待当前原生采集完成，但不等待画面 HTTP 上传。输入只有在原生应用成功后才确认，取消后排队输入丢弃，收尾显式等待松键，新会话等待旧会话完成清理。
- 输入最多 128 项，一批最多 32 项，单调序号、重试去重、接收方确认后清除；溢出直接结束会话。物理输入绑定显示器，切屏后旧输入释放并丢弃，仍推进确认，不作用在新屏。界面失焦时丢弃尚未发送的物理输入，再排入释放；设置命令保留。
- 双方使用 Noise 加密的随机挑战/应答心跳；只有当前未消费、未过期挑战的回应能续期，超过 5 秒没有新回应就停止。服务端重放旧状态不能延长控制。控制端的短暂只读轮询故障可有界重试，其间暂停并释放输入；重新连接必须重新批准，不重放旧输入。
- 会话结束携带稳定原因：主动停止、拒绝、过期、断网、设备撤销、采集或输入失败。拒绝、过期和撤销由服务端认定，只有被控端可报告原生故障；第一次原因保留，后续清理不覆盖。设备撤销后，已失效令牌仍被拒绝，仍合法的另一方只能读到已清除画面的结束元数据。普通结束用温和状态公告，故障用错误公告。
- 本机停止、失焦、页面卸载、账户更替、输入失败、显示器切换与退出都释放已按下的键鼠。关闭主窗口结束远程会话，新的被控请求会叫出主窗口。Esc 始终释放本机键盘焦点，工具栏另可向远端发送 Esc。退出时显式等待工作线程，远程会话阻止空闲自动更新重启。输入库的日志在全局日志入口强制过滤，即使启用 trace 也不能记录键入文字。
- 使用标准 `Noise_XX_25519_ChaChaPoly_SHA256`（snow 0.10.0），每次会话生成临时密钥，只留在 Rust 内存。三步握手绑定会话与双方设备；双方显示本地握手摘要生成的 96 位核对代码，被控端必须核对后允许。握手可以在等待批准时进行，不能启动采集。仅显示代码不等于用户已经核验身份；如果没有实际核对，不能声称防住了主动中间人。
- 画面、输入、剪贴板和系统声音使用按类型、会话、方向与序号绑定的密文信封，分片和总大小均有界；Rust 解密后再次验证。传输 nonce 由每个方向唯一递增分配器预先分配，失败不复用。服务端只能看到公开握手、路由元数据与密文；结束清空队列，客户端即使结束 HTTP 失败也销毁本机密钥。内容不入库、不记录日志、不做录像。审计只记录会话标识与生命周期。此变更不使既有文件传输或云盘自动获得端到端加密。
- 剪贴板为用户点击或 Ctrl/Command+V 主动触发的纯文本，最大 48 KiB。正文只由 Rust 读写，不进界面、日志或快照。排空输入后，以认证的输入屏障、请求 ID、10 秒期限与成功回执保护粘贴顺序；迟到结果不污染新请求。超时意味着结果不确定，提示先检查远端，不能盲目重试粘贴。
- 系统声音默认关闭；Windows 只读 WASAPI 输出回环，Mac 用 ScreenCaptureKit 系统音频，不回退到麦克风。48 kHz 双声道、20 ms Opus；本机原始样本、网络密文队列与 WebAudio 播放排期都有界。静音/结束立即停止并清理；采集失败只关闭声音，画面继续。CPAL 的调度降级、欠载与已自动恢复的路由变化不使音频流失效，设备移除等实际故障才停止。
- 助手只获得 `assemble_remote_devices`，列出当前账户的 Windows/Mac 设备。连接、批准、屏幕与输入不开放给助手。

## 验证边界

服务端真实 HTTP 测试覆盖三步握手、批准、方向限制、账户/设备隔离、密文篡改、输入确认与重试、剪贴板、音频、撤销及关闭清空。核心测试覆盖 nonce/信封绑定、心跳重放与过期、剪贴板屏障、真实 H.264/Opus 编解码、显示器输入绑定。React 测试覆盖具名桥接、队列、视频链恢复、StrictMode、语言切换与批准前失焦。两侧读取同一份快照样本，密钥不进入契约。

本机 Windows 原生探针通过 H.264 采集/解码、系统声音 Opus 采集/解码，以及真实画面经加密本地中转取回摘要核对。只报告有限元数据，不保存内容、不移动鼠标或键入。软件探针不替代双机、真人核对代码、真实粘贴/键鼠和 Mac 权限验收；Mac 原生音频本轮未在 Windows 编译或运行。最新验证、真实启动和上线状态见[远程手册](../runbooks/remote.md)。
