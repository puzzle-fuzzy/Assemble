# 影视模块移植计划

日期：2026-11-25。状态：代码、本地集成与正式网页发布已完成；Windows 安装包已交付，安装版更新与真人写入验收单独进行。证据与限制见[影视手册](../runbooks/media.md)。

## 已确认范围

用户要求参考 `R:\jarvis` 影视部分，把管理端与桌面端体验接入 Assemble，随后明确新增纯展示 ToC。

- 管理端维护共享片库，接通真实搜索导入、编辑与影视维护功能；这取代管理端在影视领域“只读”的旧范围，不扩大账户管理权限。
- 桌面端以列表、详情为主，提供共享片库和本人私人片库。
- 新增 ToC 海报墙与详情展示，支持想看、在看、已看三个筛选状态；默认部署到 Assemble 同源 `/movies/`，复用当前服务，不切换 Jarvis 的旧站点。
- 共享片库允许匿名浏览；磁力链接只有登录后返回。私人片库、私人图片和私人观后感只有本人可访问。ToC 只提供展示、筛选和读取，写入在管理端或桌面端完成。
- 沿用共享 shadcn、Lucide、简体中文/English 和浅色/深色/跟随系统；保持 Assemble 现有菜单、账号和文件传输行为。
- Jarvis 只读参考，Assemble 使用自己的 Rust 服务端与账号、新数据，不搬迁旧业务库或账号凭据；来源配置仅按用户单独授权复用受保护的 TMDB Token。

## 参考内容与差异

已核对 Jarvis 的 `apps/admin/src/features/media`、`apps/web/src/daily/media.tsx`、`apps/media-web`、`apps/api/src/media`、`packages/media-contracts` 与 `packages/media-client`。

管理端参考片库表格、筛选、资料核对/导入、状态与观影记录、图集/主封面、合集和统计。展示端参考海报墙、详情、演员作品、合集、缺图与加载恢复；不复制另一套基础控件或 Jarvis 账号逻辑。

Jarvis 的公开库原本仅允许想看/已看；本项目按用户确认支持三种状态。Jarvis 公开磁力的旧决定不适用于本项目，匿名响应必须在服务端删去磁力值，而不是仅隐藏按钮。

## 实现边界

1. 在 `assemble-protocol` 定义共享影视类型与校验，服务端追加迁移，Rust 客户端与具名桥接一起接入。已有迁移不改。
2. 服务端负责权限、版本冲突、来源身份去重、导入任务、图片校验及保管；TMDB 密钥只在受保护服务端配置中读取。豆瓣访问受限时返回明确来源错误，不读取私人 Cookie 或绕过验证。
3. 桌面端仍只经 Rust 请求数据。海报通过受控具名图片命令读取为图片数据，不把设备令牌、服务器任意 URL 或本机路径交给页面，也不放宽通用联网/文件能力。
4. 共享与私人按独立归属去重，私人条目不能因为加入共享片库、合集中包含同名电影、猜测标识或图片缓存而公开。合集仅引用共享条目。
5. 两端共享 `packages/media` 的 TypeScript 模型、校验、浏览器适配和业务展示组合。底层组件仍只有 `packages/ui` 一份。
6. ToC 使用独立的 `apps/media-web` 构建，随服务端镜像发布。浏览器登录跳回固定 `/movies/`，不内嵌登录、不处理密码、不存认证令牌。
7. 磁力只存储与复制，不在服务端运行 BT 下载。图片与导入具有大小、像素、并发和存储边界；任务必须有真实阶段与失败恢复，不制造假百分比。

## 实施顺序

1. 固定协议、权限与响应投影，完成真实存储及共享/私人增删改查。
2. 接入资料源、导入任务、封面图集、合集、演员作品及统计。
3. 管理端维护页面、桌面列表详情、ToC 海报墙并行接入，完成中英和主题。
4. 验证跨账户拒绝、匿名响应与图片边界、版本/幂等/失败恢复，以及界面真实动作。
5. 全仓 `bun run verify`、真实服务和 Windows 启动、Docker 构建，再提交推送并按既有手册部署。资料源密钥未配置时明确列出缺失配置，不把夹具测试当作来源真实可用。

电影在独立工作树开发，主工作区的网络下载任务继续保留；合并时专门核对共同修改的 Cargo、协议入口、桌面命令/状态与菜单。
