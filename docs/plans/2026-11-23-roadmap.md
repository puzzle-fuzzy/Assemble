### 1. 把已经上线的验收修好

不加新东西。分两条线：能自动做的由助手做；要点界面的由你走一遍，哪里不对助手来修。2026-11-26 起和后面的新功能并行，不再挡着它们。

**助手先做的（不需要你在场）：**

- 桌面端写一份本机日志。从启动台或托盘启动的进程没有可见的错误输出，以前"哪里不对"无从查起。现在日志同时写标准错误和系统给应用留的日志目录里一个限大小的文件（macOS：`~/Library/Logs/com.puzzlefuzzy.assemble/desktop.log`），不含凭据。
- 网络下载的几处收尾：开始前看磁盘余量，不够就说清楚；磁盘写满时是它自己的一个错，不和别的存储故障混在一起；启动时清掉上次崩溃留下的暂存目录；PATH 里找不到 FFmpeg 时再去几个常见安装位置看一眼（从启动台启动的应用拿不到你 shell 里的 PATH）。

- 文档收口：把十几处过时或矛盾的说法改准，这份路线图就是其中之一。
- 统一版本：让持续集成按最新代码打两个平台的安装包，这台 Mac 由助手更新，Windows 那份由你装。
- 本机签名：2026-11-26 做完。换新构建时钥匙串反复问用户，根子在应用没有稳定的签名；现在这台 Mac 上构建出来的程序都由同一张本地自签证书签名。它只管这件事，不是第 3 步里分发用的签名。

### 2. iPhone 应用（原生 Swift）

你 2026-11-25 定的：手机走原生 Swift，不借第三方的推送类应用。2026-11-26 又定了两件：**Apple 开发者账户先不买，以后会买**，所以做到不买也能做的那一步为止；**手机上的提醒先做本地通知，远程推送放第二期**。

你列的九项里有三项属于它：

- **日程与提醒在手机上**：名单，到点的通知。
- **手机二维码登录**：不用反复记账号密码；同时保留账号密码登录，应付电脑不在的时候。
- **用 NFC 唤起**：拿手机碰一下标签就能唤起应用并做一件事。具体怎么做，到这一步核实了再写。

具体方案到这一步再出。已经知道的：手机拿到设备令牌之后，看日程、改日程、标已读这些接口现在就能用；要改的是登录的回调地址（现在只认本机回环地址）、设备的平台里加上 iPhone（旧版桌面应用遇到它会读不了设备列表，所以要先升两台电脑上的应用）、推送。这台 Mac 有 Xcode 26.6 和 iOS 模拟器；参考 jarvis 的 iPhone 应用（Swift + SwiftUI，只靠扫码登录，只在前台同步，只用本地通知）。

完成标准待方案出来再定。最少的一条：对助手说一句话建出的日程，到点时 iPhone 也响。

### 3. 签名与分发

- 开发机上的本地签名已经有了（2026-11-26，你同意的）：一张自签证书，构建完自动签，只为了让钥匙串认得每一次构建。它和下面这几件不是一回事。
- macOS 的签名与公证；Windows 的安装包与签名。要证书，买不买由你定。iPhone 应用的签名在买 Apple 开发者账户时一起解决。
- 自动更新：2026-11-27 你定了要做，已经做进来（[决策 0015](../decisions/0015-desktop-auto-update.md)）：整包更新、由自己的服务器下发、空闲时换上；签名用的私钥只在发布用的那台 Mac 上。带更新器的第一版要在两台电脑上各手动装一次，之后的版本才会自己更新。Windows 真机上的静默安装、正式服务上的第一次发布，还没有做过。
- 发布页：现在安装包只在每次构建的页面底下，要登录 GitHub 才能下载；要给别人装的话得挂到发布页上。

完成标准：一台没装过开发环境的电脑能装上并用第 1 步的全部功能。

### 6. 远程控制

你 2026-11-25 定的：两台电脑互相控制——文件传输和画面。2026-11-27 要求参照 `E:\desk-link` 继续补齐，并明确保留同账户、被控端逐次批准和服务端中转。源码已接入 H.264/JPEG、画质选择、双向纯文本剪贴板、系统声音、1:1 拖动浏览、全屏与光标位置；Noise 握手后双方核对代码再批准，远程内容加密中转。文件复用原有发送面板。跨账户、直连、无人值守与免确认重连不纳入；还没有正式发布与双机验收。技术与限制见[决策 0017](../decisions/0017-remote-desktop-first-batch.md)，验证见[远程手册](../runbooks/remote.md)。
