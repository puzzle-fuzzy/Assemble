## 现在在哪

已经有的：

- 服务端：账户与登录页、桌面授权、设备与在线状态、事件流、发送到设备、云盘、定时清理。
- 桌面端：登录流程与设备列表、接收（自动落盘、通知、回执）、发送（面板里选云盘或设备）、云盘视图、发起发送的入口。
- 正式服务：<https://as.yxswy.com>，部署在 yxswy 的服务器上。从外网核对过，但**还没有人在上面登录用过，第一个账户也还没有建**。
- 持续集成：仓库是公开的（[puzzle-fuzzy/Assemble](https://github.com/puzzle-fuzzy/Assemble)），每次推送在 macOS 与 Windows 上各跑一遍验证、构建服务端镜像；打标签或手动触发出安装包。两个平台的验证都全绿过，Windows 的安装包构建成功过。
- [日程规划的方案](2026-11-24-schedule-planning.md)：第一批是日程、提醒、到点通知，加上给 Codex 和 ZCode 用的对话入口。

还欠着的：**没有真人在真实运行里把它们用过。** 登录之后的每一步——收一个文件、发一个文件、用云盘、看通知——目前都只有对着真实服务端跑的自动化测试。

## 接下来

按先后排。

### 1. 在正式服务上开始用

1. **建第一个账户**（密码只能你自己设，所以这一步由你来做）：

   ```sh
   ssh -t yxswy.com 'cd /opt/assemble && docker compose exec assemble assemble-server create-account <用户名>'
   ```

2. **装应用**。安装包从持续集成来（[运行手册](../runbooks/verify-macos-launch.md)的"安装包从哪来"），连的是正式地址。它们没有签名：macOS 上第一次打开要在"系统设置 → 隐私与安全性"里点"仍要打开"；Windows 上会有 SmartScreen 的提醒。
3. **在两台电脑上各登录一次，互发一个文件**，再看一眼云盘。
4. 哪里不对就告诉我。

完成标准：一台 Mac 与一台 Windows 都登录了同一个账户，互相发文件成功，收到的文件在"下载/Assemble"里，通知弹出来了。

不连正式服务、只在本机走一遍主流程也可以：`bun run acceptance`（运行手册第 1 节）。它用一台替身设备当第二台电脑，要你做的只有登录、往回发一个文件、从菜单栏退出。

### 2. Windows 真机验收并修到能用

按运行手册末尾的清单走：安装、右键菜单、单实例、开关、拖放、登录与收发、开机启动、退出。第 1 步做了，就等于走了大半。

完成标准：清单上的八条都走通。代码已经在 Windows 上编译并通过了全部测试，安装包也打出来过；但真正的应用一次都没有在 Windows 桌面上启动过，预计会有要改的地方。

### 3. 日程规划：第一批

范围和对话入口已定（决策 0003）。**还差一件事才能开工：手机上怎么提醒。** 你要日程设好之后 iPhone 上会有提醒，而 Assemble 现在没有 iPhone 应用。三个选项与我的建议都在决策 0003 里。

定了之后按[方案](2026-11-24-schedule-planning.md)里的步骤做：服务端（数据表、接口、调度、事件与补发）、给 Codex 和 ZCode 用的 `assemble-mcp`、桌面端的"日程"页、手机那一步。

完成标准：对 ZCode 说一句"我明天 9:00 的火车"，它算好提前量、把"带身份证"写进备注并建出日程；两台电脑和手机上都准时响。

### 4. 签名与分发

- macOS 的签名与公证；Windows 的安装包与签名。要证书，买不买由你定。
- 自动更新：需要先确认要不要（原来的 Electron 版没有）。
- 发布页：现在安装包只在每次构建的页面底下，要登录 GitHub 才能下载；要给别人装的话得挂到发布页上。

公司的 Windows 电脑能运行没签名的程序（你 2026-11-24 确认过），所以验收阶段不签名也行。

完成标准：一台没装过开发环境的电脑能装上并用第 1 步的全部功能。

### 5. 补齐文件传输的边角

都不大，排在日程之后或者见缝插针：

- 桌面端的拒收：收到文件时可以选择不收（服务端的接口已经在）。
- 云盘改名在桌面端的入口；要不要文件夹需要你定。
- 断点续传：现在中断了从头再来。
- 传输记录跨重启保留。
- 收到的文件的权限：现在是仅本人可读写，要不要改成跟随系统的默认值，需要你定。
- 备份与恢复、升级：步骤都写了，都还没有在服务器上做过一次。

## 不在本路线图里

- 局域网直传与大文件分片。你选了服务端中转、单文件 100 MB 以内；要改是另一个决定。
- 迁移 jarvis 的账户与数据。新产品、新数据。
- Windows 11 右键菜单的第一层、访达的右键菜单、网页端、管理端、小程序。
- 宠物、壁纸。

## 需要你决定的事

1. **建第一个账户**，然后在两台电脑上用起来（第 1 步）。后面每一步都在等它。
2. **手机上怎么提醒**（第 3 步）：做 Assemble 的 iPhone 应用、先借一个现成的推送类应用、还是两个都要。我的建议是先用推送类应用顶上，iPhone 应用单独排一个阶段。
3. **助手怎么拿到权限**（第 3 步）：我建议让它自己登录一次，成为账户里的一台"设备"。
4. **签名证书买不买，要不要自动更新**（第 4 步）。
5. **云盘要不要文件夹**；**收到的文件要不要只有本人可读**。现在分别是"没有文件夹"和"只有本人可读"。
