## 接下来

按先后排。

### 1. 在正式服务上开始用

1. **账户已经有了**：`yxswy`，密码 2026-11-25 发在对话里了，请登录后到 `https://as.yxswy.com/web/account` 改成只有自己知道的。要再加账户，在网页上凭邀请码注册，或者用下面这条命令：

   ```sh
   ssh -t yxswy.com 'cd /opt/assemble && docker compose exec assemble assemble-server create-account <用户名>'
   ```

2. **装应用**。安装包从持续集成来（[运行手册](../runbooks/verify-macos-launch.md)的"安装包从哪来"），连的是正式地址。它们没有签名：macOS 上第一次打开要在"系统设置 → 隐私与安全性"里点"仍要打开"；Windows 上会有 SmartScreen 的提醒。
3. **在两台电脑上各登录一次，互发一个文件**，再看一眼云盘。
4. **用一次日程**：在"日程"卡片里新建一条两分钟后的提醒，到点看通知、点它定位、点"看过了"。
5. **让助手管日程**（你平时的用法）：`bun run mcp` 构建入口，`target/release/assemble-mcp login --name "ZCode 的助手"`，在浏览器里点一次"确认登录"；再用 `assemble-mcp print-config zcode`（或 `codex`）打出配置片段，自己贴进去。然后对 ZCode 说那句"我明天 9:00 的火车，提前 90 分钟提醒我，带上身份证"。
6. 哪里不对就告诉我。

完成标准：一台 Mac 与一台 Windows 都登录了同一个账户，互相发文件成功，收到的文件在"下载/Assemble"里，通知弹出来了；对助手说一句话建出的日程出现在两台电脑的"日程"卡片里，写着是哪台助手记下的，到点弹出通知，备注里带着"身份证"；"设备"卡片里看得到这台助手，移除它之后工具提示要重新登录。

不连正式服务、只在本机走一遍主流程也可以：`bun run acceptance`（运行手册第 1 节）。它用一台替身设备当第二台电脑，要你做的只有登录、往回发一个文件、从菜单栏退出。
