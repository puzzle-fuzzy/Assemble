## N1 云盘文件预览

实现与运行限制见[预览手册](../runbooks/file-preview.md)。N1 已上线；N2 目录独立实施，回收站源码已实现，分享与静态托管尚未开始。Windows 与浏览器、macOS 的实际验收分别记录，不混用证据。

### 用户效果

桌面云盘与管理端云盘的文件行提供“预览”；打开共享 shadcn Dialog，保留原列表、搜索与分页。管理员继续逐次校验已验证邮箱和超级管理员权限，普通用户只能预览本人文件。

首批支持 JPEG、PNG、WebP、UTF-8 文本，以及当前 WebView/浏览器原生支持的音视频。文本最多显示前 1 MiB，明确告知截断；视频不预先读完整文件，支持拖动进度。无法识别或不支持的文件保留下载入口。HTML、SVG、脚本、Office 和 PDF 不在首批内嵌执行或渲染，不增加后台转码任务。

### 实现约束

- 在现有 `drive`、`blobs` 与内容响应能力上增加共享预览描述；根据实际字节校验类型，不只依赖文件扩展名或上传者声明。
- 服务端预览入口使用文件标识，每次重新检查账户、文件状态与读取权限；管理员入口同时检查同源来源。内容仅对允许的类型以内联方式响应，保留 `nosniff`、禁止缓存与 Range/条件读取规则。
- 桌面只调用具名命令，不把设备令牌、真实路径、授权头或带凭据的 URL 交给 React。先验证仅供预览的 Rust 受控流入口在 Windows/macOS 上的 Range、取消和拖动行为；不能通过扩大通用文件或 HTTP capability 解决。
- 退出、换账户、删除文件或关闭弹窗时取消旧读取；预览 URL 不能在换账户后继续读取旧内容。缩略图如需新增，纳入存储计量、引用回收和预算，不成为第二套图片存储。
- 业务组合放在共享包，基础控件继续来自 `packages/ui`，中英文一起维护。MCP 增加只读预览能力描述；不将完整音视频或本机路径塞进工具结果。

### 验收

实际验证图片、文本、音频、视频及不支持格式；覆盖跨账户、未登录、非管理员、跨站读取、伪造 MIME、Range、截断文本、关闭取消和账户切换。浏览器与 Windows WebView 各实际播放并拖动一次；Mac WebView 单列验收，不能用浏览器结果替代。

## N2 云盘文件夹

已按[独立实施计划](2026-11-27-drive-folders.md)实现，实际契约、限制与验收见[文件夹手册](../runbooks/drive-folders.md)。目前未部署，N3 回收站也已在该目录模型上完成源码与本地验收。

### 用户效果

在现有云盘内新建文件夹、进入、重命名，并把文件或文件夹移入其他云端目录。顶部面包屑表达“云盘 → 文件夹 → 子文件夹”，父级可跳转，内容区不再重复提供返回按钮。搜索默认作用于当前目录。

这里的“移动”仅更改云端目录关系，不移动或删除用户电脑上的源文件；本机文件操作继续只复制、不覆盖。文件夹发送、目录自动同步和大于现有单文件上限的传输不随本包引入。

### 实现约束

- 新迁移增加账户所属目录、父目录标识与文件目录引用；既有文件全部留在根目录，原文件标识、内容与时间不变。
- 所有查询与变更逐次检查账户归属、目录版本和祖先关系。拒绝循环、跨账户挂载及移动到自身子树；目录数量、深度与分页设置服务端硬上限。
- 文件名保持当前允许同名的规则，不按名称合并或覆盖；同一父目录的文件夹名称唯一，根目录也纳入唯一性约束。名称复用现有单段名称校验，不把目录标识当本机路径。
- 新客户端通过独立 `/v1/drive/tree` 请求根目录或指定目录。旧平铺接口和类型不变，旧上传落到根；新客户端只有在新根入口明确返回 404 时回退平铺，不将目录上传退回旧入口。iOS 代码和样本不变。
- 管理端可只读按所属账户浏览目录和文件，不借此新增跨账户改名、移动或删除。目录路径是云端层级，不显示服务器文件系统路径。
- MCP 提供目录列表、创建、重命名和云端归档移动的具名工具，只收资源标识与名称。

### 验收

从已有数据升级后文件、内容摘要和配额不变；验证根目录、嵌套目录、父级跳转、重名、循环、并发修改、跨账户隔离与旧客户端读取。两台桌面核对同一账户的目录变化；任何未通过的平台按待验收记录。

## N3 回收站

[N3 独立实施计划](2026-11-27-drive-trash.md)已落实到源码：删除批次、恢复规则、旧端兼容、持久内容清理、共享界面与助手工具。实际契约和验证见[回收站手册](../runbooks/drive-trash.md)，尚未部署；首期手动永久清理，不自动到期删除。

### 用户效果

“删除”把本人云盘文件或文件夹放入回收站，可以恢复或明确永久清理。恢复回原目录；原目录不存在或仍在回收站时恢复到根目录，并在结果中明确位置。恢复文件夹时保留层级，遇到名称冲突保留双方，不覆盖已有内容。

首期由用户手动永久清理，不开启自动到期删除。后续若增加保留期限，另行确定默认值并在界面明确展示。

### 实现约束

- 新迁移保存删除时间、原父目录和恢复需要的关系；删除子树在事务内完成，不把半个目录放进回收站。
- 回收站仍计入账户配额和全站实际占用，移入回收站不释放 blob 引用、不显示虚假的可用空间。存储监控补充可回收用量，继续使用现有预警与系统通知入口。
- 下载、预览、发送、分享和助手读取逐次检查回收站状态。移入后立即停止通过原入口读取；不依赖前端隐藏。管理员回收站入口只读，不代替用户恢复或清空。
- 永久清理只释放本记录的引用；其他云盘记录、未完成发送或其他账户仍引用内容时不能删除实体。复用现有内容回收流程，失败可重试，不在数据库事务中假定磁盘删除必定成功。
- MCP 提供回收站列表与恢复；永久清理若提供工具必须是独立具名操作、指定明确标识，不能由普通删除或自动整理隐式触发。

### 验收

删除后旧内容入口不可读、恢复后原内容一致；覆盖原目录丢失、目录冲突、同摘要多引用、子树并发修改、停用账户、配额和重启。隔离环境实际完成一次删除、重启、恢复与永久清理，核对数据库引用和实体内容。

## N4 断点续传

下一步按[N4 独立实施计划](2026-11-27-resumable-transfers.md)推进，当前仅规划：先收口 N3 提交与发布，再交付 N4.1 云盘上传、N4.2 本机恢复与云盘下载，最后 N4.3 设备中转复用。现有历史不是恢复队列，服务端额度预留也必须覆盖新旧上传入口；不把一个分片接口当作完整续传。首个实现包固定为 N4.1。

承接旧清单 C3。单文件上限保持 100 MB，经服务端中转；分段是恢复机制，不扩展成任意大文件或设备直连。

- 新上传会话绑定账户、发起设备、目标目录、文件长度、整文件摘要和目标版本；初始化时预留配额与全站容量，防止并发绕过限制。
- 服务端记录已持久保存的区间，重启后可查询缺失段；重复段校验一致才幂等接受。禁止越界、重叠内容不一致和其他设备接管。
- 客户端恢复前重新核对源文件；文件已改变时建立新任务，不能把两版内容拼在一起。目标目录移动、删除或进入回收站后，旧会话必须重新核对或停止。
- 最后一段到达不等于完成；整文件长度与摘要校验、blob 发布、云盘/发送记录建立成功后才回执。取消或超时释放预留，清理超过 24 小时没有活动的暂存会话。
- 桌面仍独占本机传输任务；MCP 查询和操作使用任务标识，不接收本机路径。下载端先核对内容身份和 `ETag`，不具备恢复条件时明确重新下载。
- 全站物理去重继续存在；本包不把摘要升级成可读取其他账户内容的“秒传凭据”。客户端秒传另作受本人已有内容权限约束的后续项。

验收用确定性网络中断、服务重启、磁盘不足、取消、源文件变化、目标变化及并发额度覆盖，实际在两台设备验证恢复后的字节与整文件摘要一致。

## N5 主动分享指定文件

本包先出权限决策再实现。建议首批仅允许已验证且未停用账户主动创建自己的单文件只读分享，支持到期、最大下载次数及立即撤销；不自动公开云盘，不开放匿名上传，也不允许管理员替用户创建分享。

资源级分享链接需要在决策中明确其可展示、可复制的范围，与登录会话、设备令牌和后台存储地址严格区分；现有“凭据不进界面”的边界不因一个新 URL 被隐式绕过。分享只投影必要文件信息，不附带邮箱、设备、所在目录和其他文件。

内容访问重新核对分享、所有者、文件身份及回收站状态。删除、撤销、到期、停用立即阻止后续读取；正在进行的响应设取消机制。下载次数按一次有效下载会话计，不能按每个 Range 请求重复扣除。首批不支持整个目录公开，避免后来放入目录的文件被意外公开。

验收包含匿名访问、撤销、到期、次数竞争、文件改名与删除、停用、Range 重试，以及无关账户不能枚举分享的测试。MCP 创建和撤销分享也必须是明确具名操作。

## N6 凭码取件

依赖 N5 的资源授权与撤销规则。建议首批由已登录用户创建取件批次、主动放入指定文件；接收者在浏览器输入短码后读取该批次，无需安装客户端或输入主账户密码。

取件码与账户登录凭据不通用，使用明确有效期、猜码限速、批次容量上限及撤销能力。先支持逐文件下载，再实现经过名称与路径校验的流式 ZIP；不把完整批次加载进内存。N3 的删除与 N5 的撤销规则同样适用，计量与过期清理属于一个完整生命周期。

新网页仅提供取件所需内容，不顺带建设完整用户工作台。临时聊天房间、WebRTC、匿名投递和设备 P2P 不在本包中。验收覆盖首次取件、网络失败后重试、到期、撤销、限速及 ZIP 名称碰撞。

## N7 静态产物发布

承接旧清单 D3，参考 ZipShip 的工作流程，在现有 Rust 服务与 SQLite 内实现，不引入另一套认证、数据库或组织系统。

建议首批只给超级管理员本人使用：上传系统选择器选出的静态目录或 ZIP，检查真实入口、路径、资源引用、敏感文件及解压限额，生成不可变版本预览；明确发布后切换正式指针，保留版本历史与回滚。上传完成不能直接当作已上线。

- 用户上传的网页必须使用独立访问来源，不能放在 `/admin/`、`/movies/` 或其他携带 Assemble 会话的来源下，也不能复用带签名的桌面更新包发布通道。
- 独立来源、Cookie 隔离、`Host` 校验、脚本策略、SPA 路由和缓存策略先在隔离环境完成实际浏览验证；新增域名、解析、证书及共用 nginx 变更在部署前按手册确认。
- 每站 100 MB、每账户五站、全站 500 MiB 作为沿用 D3 的建议初始预算；包含版本与暂存的空间核算须进入容量准入，不能只统计当前发布版。
- 发布和回滚具备版本校验、实际指针切换与审计；旧版本正在被读取时不能先删内容。故障后可以核对当前真实版本，不以任务入队当成功。
- MCP 首批只提供该账户已获授权的具名站点列表、版本查询和明确发布/回滚工具；不接受任意服务器路径、shell、nginx 配置或原始 API 请求。
- 不包含源码构建、Git 自动构建、组织协作、任意自定义域名、自动 HTTPS、通用 API Token 或通用 Webhook。

验收上传普通 HTML 与一个实际 SPA，核对资源、版本预览、正式切换、回滚、Cookie/账户隔离、路径穿越、ZIP 炸弹与容量限额；镜像必须真实构建启动，不能只通过前端构建后就部署。

## 共同实现与验证规则

1. 开工时用 CodeGraph 与源码核对实际基线；当前主要关联 `assemble-protocol`、`assemble-client`、`assemble-store`、`assemble-transfer`，服务端 `drive`、`blobs`、`storage`、`sends`、`admin`，以及桌面命令、状态、桥接和 MCP。不因一个公共文件有其他会话改动而覆盖它。
2. 契约先行：Rust 类型、服务端、客户端、具名命令、TS 校验与快照、MCP 和中英字典一起完成；新字段兼容缺省，新增错误用稳定错误码，不向用户展示 Rust 诊断。
3. 每包只新增自己的迁移，编号以落地时已提交清单为准，不预占连续号码、不改历史脚本。覆盖空库、已有数据升级、备份恢复和引用完整性。
4. UI 共用 shadcn 与既有主题。管理端表格默认 20 条；动作紧凑，父级导航进入面包屑，详情与表单用弹窗。无内容时仅给必要文字，状态能由操作或图标明确表达时不重复加说明。
5. 开发与实际启动使用隔离目录、合成账户和可核验的文件；不读取真实密码、不预置正式会话、不创建临时正式账户，也不为了参考功能而启动已停用的 Jarvis。
