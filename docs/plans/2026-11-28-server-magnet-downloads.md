# 磁力改为服务端下载与 HTTPS 回传

状态：源码与真实回环集成已完成；线上升级、Mac 安装与公网资源验收以各环境实际回执为准。2026-11-28 用户明确选择服务器解析、下载并通过 HTTPS 回传；不再提供客户端直连选择。本文是实现计划，不能作为上线回执。

## 原因与边界

Mac 的系统网络能访问第一方 HTTPS，但实测 BT 握手中断。仅返回服务器解析的元数据不能解决本机接收 BT 分片的问题。因此磁力的节点发现、元数据获取、BT 分片、上传限速都移到服务器；Mac 只访问固定的 Assemble 服务来源，保留本机选择位置、校验、无覆盖发布与队列。

- 普通已认证设备使用独立的私有接口；不开放管理员 DHT 观测接口，不把私人任务导入全站观测库。
- 元数据按 v1 信息哈希验证。服务器所有节点、Tracker 和重定向仍只允许公网；不开放 BT 入站或 UPnP。
- 来源只在 Rust 内存和客户端钥匙串里。服务器恢复只保存已校验元数据、文件选择和任务标识，不保存原始磁力或 Tracker 凭据。
- 每任务 BT 上传仍限 256 KiB/秒；完成即停。Mac 暂停或退出时请求停止服务器任务；心跳超时也暂停，服务器重启不自动续跑。
- 服务器任务、状态、文件、分片与回执逐次核验账户归属。稳定请求键避免重试重复创建。
- 服务器临时文件计入全站存储预算，另限账户、并发、元数据与保留时间；取消或本机确认落盘后清理。预算在实际文件删除之后才释放。
- HTTPS 回传按固定分片 SHA-256 校验，并核对整文件长度与摘要；已有本机缓存通过摘要才能复用。最终仍先暂存、校验，再无覆盖发布。
- 保留旧本机记录与缓存；继续旧任务时经服务器重新建立任务，能通过分片摘要验证的缓存可复用，不再连接本机 BT 节点。
- 本轮先验 Mac；Windows 不做专项功能或真机验收。

## 结构

共享协议定义私有预览、稳定开始请求、任务控制、状态与文件分片清单。`assemble-client` 是 Mac 对第一方服务的唯一 HTTP 出口。`assemble-download` 复用校验、队列与发布，增加托管 BT 核心和 HTTPS 接收；桌面壳只注入已有客户端。服务端增加薄路由、账户隔离、持久准入与回收、心跳租约。

## 验证

先验证解析、实际 BT 收片和 HTTPS 落盘；再验证选择、暂停后不增长、续传、活跃时退出、重启保持暂停、恢复后复用已校验缓存、取消与清理。自动化覆盖身份隔离、输入边界、幂等、预算竞争、租约过期、服务重启和损坏分片。发布前全量验证，再构建服务端镜像、按部署手册备份升级，安装 Mac 并做真实验收。
