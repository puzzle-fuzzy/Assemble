## 交付目标与顺序

先让用户删掉的云盘内容可以找回，再进入 N4 断点续传。N2 的提交、CI 与发布状态单独核对：可以基于已经合入的目录模型开发 N3，但不能把 N2 的源码合入写成已经上线，也不能用 Windows 验收代替 Mac。

N3 上线前先完成所依赖 N2 的备份、迁移与发布检查；N3 仍独立提交、验证和发布。桌面更新只能走现有签名发布流程，本计划不改更新器或替用户安装应用。

首期提供三个动作：移入回收站、恢复、明确永久删除。不开启自动到期清理；永久删除按选定的一次删除记录执行，不提供一键清空全部或助手自动清空。

## 用户看到的界面

1. 在云盘内提供同级的“文件 / 回收站”入口，复用共享表格，不新增长期占位的侧栏菜单。当前面包屑表达“云盘 → 回收站 → 删除的文件夹”，可点击父级，不再放重复标题或返回按钮。
2. 普通列表“删除”改为“移入回收站”。单文件保留简洁确认；文件夹确认弹窗显示将影响的文件数、文件夹数和字节量，不把内容逐条塞进弹窗。
3. 回收站按一次删除显示一行：名称、原位置、删除时间、文件数量与大小。文件夹可只读查看该次删除包含的层级，首期按整次删除恢复，不单独抽取其内部子项。
4. 行内提供“恢复”和“永久删除”。永久删除使用独立确认弹窗，取消默认聚焦；不把普通删除或关闭弹窗解释成永久清理。
5. 搜索仅作用于当前回收站列表，输入框用 placeholder 与可访问名称，末尾图标清空。空表只显示必要文字，不加图标。桌面默认每页 10，管理端默认 20；按钮文字完整展示。
6. 恢复成功后保留回收站列表位置，并提供一次“查看位置”操作，进入真正恢复后的目录。原目录失效或重名导致位置、名称调整时，只在确认与结果中解释，不新增常驻说明栏。
7. 管理端按所属账户只读查看回收站元数据和容量，不代用户恢复或永久删除；首期回收站内不提供预览、下载，恢复后使用既有文件入口。

新增系统文案同时维护简体中文和英语；用户名称、原路径文字和文件内容不翻译。时间沿用桌面本地时区与管理端现有时间规则，不因语言切换改变时区。

## 删除与恢复规则

### 一次删除是一个独立批次

- 单文件或整个活动文件夹子树构成一个批次，保存真实删除时间、原父标识和原位置显示快照；资源标识、文件内容摘要、创建时间保持不变，变更版本递增。
- 删除文件夹时只包含当时仍活动的后代。此前已单独移入回收站的子项保持自己的批次，不随父文件夹重复删除、恢复或永久清理。
- 目录删除前先读取影响摘要，返回子树修订值。确认写入时在同一写事务内重算并比较，不能只检查根文件夹版本：N2 的根版本不会因内部新增文件自动变化。
- 并发上传、移动、新建或改名改变了影响范围时，整次删除拒绝并要求重新核对。先提交的上传计入新摘要；先提交的删除使后到上传拒绝，不偷偷存到根目录。
- 首期每批最多 5000 条实际文件与文件夹记录；超过时在预检查和事务中整批拒绝，不用多次小删除伪装成原子子树操作。API 查询每页 1～100，搜索最多 200 字符，排序按删除时间、批次标识降序稳定排列。

### 恢复保留双方，不覆盖

- 原父目录仍属于本人且处于活动状态时，恢复到其当前位置；原父已被永久删除、仍在回收站或恢复后将超出 16 层时，恢复到根目录，并明确返回实际位置及原因。
- 文件仍允许同名。文件夹遇到同级重名，生成合法且确定的“名称（恢复）”“名称（恢复 2）”等名字，按 UTF-16 长度上限截取原名，不能合并现有文件夹。
- 恢复预检查展示实际目标和必要的名称调整。确认时复核目标、重名与子树深度；若结果会变化，返回冲突并重新确认，不静默换到另一个位置或名字。
- 内部父子关系、文件内容及标识保持不变。批次以外的独立回收记录不会被带出；后来恢复原父目录，也不自动搬动此前已经恢复到根的记录。
- 移入、恢复及永久删除均检查账户归属、未停用身份和最新版本。请求重试不能重复建批次、重复恢复或重复扣内容引用；回执只返回原操作结果，不能把已经恢复的内容再次删除。

## 数据模型与兼容

新增迁移，不改 `0014_drive_folders.sql` 或 `0015_activity_log.sql`。本轮迁移固定为 0016_drive_trash.sql。

实现已在原文件和文件夹记录上保存回收批次归属，另建账户所属批次、恢复位置及最小操作回执。删除根暂时脱离原父外键，原父标识作为恢复信息保存，批次内部保留父子外键；这样原父永久清理后，独立删除的子项仍可恢复。文件夹同级唯一索引改为只约束活动目录，回收站不能占着活动目录名称。

活动读取统一检查回收状态，不能分散依赖前端筛选。至少覆盖：

| 入口                                                 | N3 要求                                                |
| ---------------------------------------------------- | ------------------------------------------------------ |
| 新目录与旧平铺列表、搜索、面包屑、移动目标           | 只返回活动记录，不允许活动子项挂在已删除父级下         |
| 文件详情、内容、预览描述、预览媒体、Range 和条件读取 | 每次请求核对活动状态，包括管理员入口                   |
| 上传的前置检查和最终登记事务                         | 目标仍存在且活动，否则拒绝并清理未引用暂存内容         |
| 管理端全站文件、按用户目录、日志对象跳转             | 活动入口不把回收项当成仍可下载文件；历史日志保留原记录 |
| 助手目录、改名、移动和预览                           | 活动入口不可读回收内容，回收站使用单独具名工具         |

提交移入后，新读取请求统一按不可见处理；关闭本机相关预览、取消后续读取。不承诺撤回已经送达客户端的字节或之前保存的本机副本。此前已经建立的设备发送拥有独立内容引用，不因删除一份云盘记录而被撤回；本包不新增从云盘发送或分享入口。

### 旧版也不能绕过回收站

- 升级后的服务将旧 `/v1/drive/files/{id}` 和 N2 普通 `DELETE` 文件入口改为内部移入回收站，成功保留原 204 响应形状，不允许它们继续永久删除。旧 N2 空目录删除入口仍检查为空，再移入回收站；删除非空子树只走新预检查与确认入口。
- 无版本的旧文件 DELETE 无法区分一次迟到重试与新的删除意图，因此对曾经恢复的资源拒绝写入并要求更新客户端；不能让旧重试把刚恢复的文件再次移入。带版本的 N2 入口以恢复后递增的版本拒绝旧请求，不能为兼容放宽检查。
- 旧 UI 可能仍写“永久删除”，但升级后的服务只执行更保守的移入；新客户端必须更新文案和容量说明。永久删除必须是独立回收站 API，不复用普通文件 DELETE。
- 新桌面先探测回收站能力。旧服务不支持时，明确提示更新服务并禁用新删除流程；不能回退旧永久删除接口。发布次序先服务端、后桌面。
- 旧类型和原内容地址形状不变；可回收条目不进入旧名单，但其逻辑字节仍计入原配额字段。iOS 与其样本不因本包改动。

## 配额、永久清理与存储监控

移入回收站不复制文件、不释放 blob 引用，活动文件加回收文件继续计入账户逻辑配额。已有文件夹数量上限包含回收中的目录，恢复不新增数量；达到上限时让用户自行永久清理，不自动删除数据。回执与墓碑必须有账户级硬上限，触顶时拒绝新增删除批次，但不阻止已有批次恢复或永久清理，也不通过自动清空内容解决元数据上限。

管理端补充回收站逻辑用量与预计可释放的物理内容量，两者明确区分。物理量按摘要去重，仅计入所有剩余引用都在本次可清理集合内的内容；其他账户、活动云盘文件、待接收发送仍引用时不能算作可释放。无法可靠测量时返回未知，不编造零值。继续复用现有存储预警和系统通知入口。

永久清理分成两个阶段：

1. 在写事务中验证批次版本、删除云盘记录、精确扣减相应内容引用并写入持久清理任务。整次失败回滚；重复请求不会再次扣引用。账户逻辑用量随提交更新。
2. 事务外按任务清理实体，失败保留并重试，重启继续处理。真正清理前再次核对引用；如果内容又被使用，则取消该实体删除。磁盘与全站可用量按实际清理结果更新，不能在提交元数据时就宣称已经释放磁盘。

本包已实现事务扣引用与持久清理任务，并让发布、登记、release、discard_unreferenced、sweep 与清理器遵守同摘要租约；文件 I/O 不放进长期数据库写事务。普通云盘 DELETE 已改为移入，不立即释放内容。

不通过扫描并删除整个 blobs 目录实现“清空”。审计记录区分移入、恢复、永久删除和实际清理失败，保存操作者、设备及必要对象元数据，不记录凭据、本机路径、文件正文或新授权地址。

## 代码与契约的落点

以下接口已由 `assemble-protocol` 固定类型，并同步服务端、客户端与两侧测试；详细字段见回收站手册。

| 入口                                                    | 用途                                                 |
| ------------------------------------------------------- | ---------------------------------------------------- |
| `POST /v1/drive/trash/preview`                          | 核对活动项目，返回删除范围、最新版本和子树修订值     |
| `POST /v1/drive/trash`                                  | 带稳定请求标识、版本与修订值移入，返回批次结果       |
| `GET /v1/drive/trash`、`GET /v1/drive/trash/{id}`       | 本人分页删除批次；详情按父标识分页读取该批次只读层级 |
| `POST /v1/drive/trash/{id}/restore-preview`             | 计算实际恢复父级、名称、冲突与深度，形成确认依据     |
| `POST /v1/drive/trash/{id}/restore`                     | 按批次版本及已确认的恢复方案原子恢复，返回实际位置   |
| `DELETE /v1/drive/trash/{id}?version=`                  | 独立永久删除，返回持久清理回执，不假装实体已删除     |
| `GET /v1/admin/drive/trash?accountId=` 及受保护批次详情 | 管理员按账户只读查看，无管理员写入入口               |

所有时间使用现有 Timestamp，批次与文件夹都是资源标识，原位置字符串只用于显示。本人接口逐次验证设备身份；管理端继续验证已验证邮箱、超级管理员和同源 HttpOnly 会话，所有敏感读取禁止缓存。恢复修订值只用于并发比较，不是授权凭据。

桌面在 `commands.rs`、`bridge.ts` 和 handler 清单新增具名回收站能力；列表、弹窗、焦点与双语文案放在共享 UI 组合。快照与两端类型守卫一起更新；关闭、退出、切换账户后取消旧查询并清空旧批次和草稿。

MCP 新增 `assemble_drive_trash_list`、`assemble_drive_trash_restore`；普通文件夹删除工具改为移入且仍保留空目录限制和破坏性标注。首期不增加永久清空工具，返回仍只含安全元数据。

| 顺序 | 交付                                  | 必须先通过的验证                                                                                                       |

| 3    | 永久清理与存储统计                    | 同摘要多引用；清理中重新上传；事务后进程中断；I/O 失败重试；重复请求；重启无少扣、多扣或误删                           |
| 4    | 桌面、管理端和 MCP 接入               | 共享表格、紧凑按钮、弹窗确认、面包屑、焦点恢复、双语、旧服务禁用退路、账户切换及工具隔离                               |

Mac 和两台真实桌面的结果单列记录，不能用自动化或 Chrome 替代。正式发布前独立中文提交、检查 macOS/Windows/服务端镜像三项 CI、备份数据库与 blobs、演练恢复后再切换。未经该步骤不执行正式数据清理。

完成 N3 后，再进入 N4 断点续传；分享、取件码、静态托管继续保留各自权限与发布来源的决策门槛。
