## 建议结果

新增独立的“网络文件下载”页面，页内提供“M3U8”和“抖音视频”两种来源。解析、下载、合并、校验和文件发布都在当前电脑的 Rust 侧执行，FFmpeg/FFprobe 也在本机运行。

本机下载不经过 Assemble 正式服务器，不占云盘配额，不要求服务端在线；建议作为不依赖 Assemble 登录的本机工具。下载成功后，用户可以打开文件或在文件夹中显示。是否再上传云盘或发给设备，是现有文件传输能力的另一次操作。

本机网络下载不套用现有设备传输的 100,000,000 字节限制。下载后的文件如果要进入现有云盘或设备发送流程，仍遵守该流程原有上限。新下载器自身设置总量、分片数、并发、超时和磁盘余量边界，具体数值随样本验证确定。

## 页面与操作

1. 左侧文字菜单新增“网络文件下载”，窄窗口的功能菜单同步增加入口。
2. 选择 M3U8 或抖音视频，粘贴地址。抖音允许粘贴完整分享文案，从中提取唯一的有效分享链接；多个链接时让用户明确选择，不猜目标。
3. 解析后展示真实标题、可取得的时长与清晰度；M3U8 主清单有多个版本时可以选择清晰度。未知信息显示未知，不编造大小或百分比。
4. 点击“开始下载”，下方任务列表展示当前阶段、实际进度、已下载字节、速度和错误原因；提供取消、失败重试、打开文件、在文件夹中显示。
5. 默认保存到系统下载目录下的 `Assemble/网络下载`；可通过系统目录选择器修改。目录路径留在 Rust，界面只展示目录简称和任务标识。

下载阶段与合并阶段分别显示。M3U8 以已完成分片数/总分片数报告真实进度；普通视频在长度已知时显示字节进度，否则显示实际下载量。合并使用 FFmpeg 的结构化进度，不用定时器伪造百分比。最终文件发布成功之前，不显示“已完成”。

页面延续现有 sidebar-13、共享 shadcn 组件、简体中文/English 与浅色/深色/跟随系统，不借新功能重新设计现有传输页。

| 来源           | 建议支持                                                                                                   | 处理结果                                                          |

| M3U8 点播网址  | 主清单与媒体清单、相对分片地址、常见 TS/fMP4、独立音轨、初始化片段及字节范围、可正常取得密钥的普通 AES-128 | 分片下载后合并；编码适合 MP4 时无损封装为 MP4                     |
| 本地 M3U8 清单 | 建议一并提供系统文件选择器导入；仅下载清单指向的 HTTP(S) 内容，相对地址需提供原始清单网址作为基准          | 不把清单中的本地路径或任意协议交给 FFmpeg；缺少基准地址时说明原因 |
| 抖音单视频     | 完整视频地址、`modal_id` 页面、`v.douyin.com` 短分享链接与包含这些地址的分享文案                           | 解析目标视频，优先下载包含音画的真实媒体文件                      |

M3U8 首版聚焦有结束标记的点播；直播录制需要时长、停止和持续空间管理，留作后续独立能力。DRM 或当前无法正常访问的来源明确返回不支持/来源不可用。图集与账号批量下载不混入本次单视频交付。

FFmpeg 优先使用 stream copy，不自动进行耗时、有画质损失的转码；不能正常封装为目标格式时报告不兼容，不把其他容器改个 `.mp4` 后缀冒充结果。[FFmpeg streamcopy 文档](https://ffmpeg.org/ffmpeg.html#Streamcopy)

## Jarvis 的参考价值

已只读查看 `R:\jarvis\apps\api\src\downloads` 及相应测试。其现有功能是公开网页加服务端解析/流式转发，并非桌面 Rust 下载器；现有下载模块也没有 M3U8 分片合并。这里复用的是规则和验证经验，需重新写成 Assemble 的 Rust 实现。

- `source.ts`：识别视频/短链/`modal_id`，展开短链；先取分享页结构化数据，再走匿名详情回退；只接受与目标 `aweme_id` 一致的数据。选择完整 MP4，避免误拿只有画面的 DASH 表示；读取实际媒体字节识别类型，拒绝把 HTML 验证页存成视频。
- `network.ts`：每跳重定向重新检查公网地址，DNS 解析后固定实际连接目标；匿名会话只用于指定抖音 HTTPS 来源，不读取私人浏览器 Cookie。匿名初始化和签名逻辑需一并评估、移植，不能只复制一个详情接口 URL。
- `download-source.test.ts`、`download-network.test.ts`：分享页被拒后的回退、目标 ID 不符、分离音轨、非法地址/重定向和媒体类型等测试场景可转成 Rust 夹具。
- `docs/downloads.md`：来源可被删除、限制匿名访问或改变响应，不能据现有代码保证任意公开视频都能解析。实现前先在当前网络上做真实可行性验证，再承诺支持范围。

首版不要求用户提交抖音密码或私人 Cookie，也不打开一个嵌入式登录网页。解析失败给出清晰原因，不用第三方未知解析站掩盖失败。

## 核心流程

```mermaid
flowchart LR
    A[桌面输入地址或选择清单] --> B[Rust 来源解析与网络检查]
    B --> C[生成受控下载计划]
    C --> D[Rust 下载到本机任务暂存区]
    D --> E[FFmpeg 本地合并或封装]
    E --> F[长度与媒体检查]
    F --> G[无覆盖发布最终文件]
    G --> H[更新任务记录与界面]
```

抖音已有完整媒体文件时，可以跳过不必要的合并。M3U8 的清单、分片、初始化片段、密钥和重定向由 Rust 逐项处理；向 FFmpeg 提供由程序重建、只引用本任务已下载文件的本地清单。不能只检查第一个 URL 后，就放任 FFmpeg 根据远程清单访问本地文件或任意网络目标。[HLS 清单规范](https://www.rfc-editor.org/rfc/rfc8216.html)、[FFmpeg 协议控制](https://ffmpeg.org/ffmpeg-protocols.html#Protocol-Options)

任务状态建议为：`resolving`、`queued`、`downloading`、`muxing`、`verifying`、`completed`、`failed`、`cancelled`、`interrupted`。任务之间有并发上限，HLS 分片有单独的并发上限；有限重试与取消信号贯穿解析、传输和子进程。

保留本机任务历史。应用重启后，未完成记录标为中断，不能假装仍在下载；重试需重新解析来源，过期地址需要更新。首版不承诺跨重启、跨来源变化的断点续传。关闭主窗口按现有托盘行为继续运行；真正退出应用时显式取消请求、停止并等待 FFmpeg，清理本任务暂存内容。

## 代码划分与接入范围

| 位置                                    | 职责                                                                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 新增 `crates/assemble-download`         | 来源解析、受控 HTTP、HLS 计划、任务状态、重试/取消、媒体工具执行和任务记录；解析/状态规则保持可脱离窗口与真实网络测试 |
| `crates/assemble-protocol`              | 下载请求、来源类型、可展示任务状态和稳定错误码；不包含 Cookie、密钥、内部 CDN 地址或本机路径                          |
| `assemble-transfer` / `assemble-device` | 优先复用流式落盘、摘要、目录与文件名边界、暂存发布；不复制一套绕开既有规则的文件逻辑                                  |
| 新增桌面壳下载编排模块                  | 持有下载 runtime；对接系统选择器、生命周期和状态推送，不实现来源业务规则                                              |
| `commands.rs` 与 `bridge.ts`            | 对应增加解析、开始、取消、重试、选目录、打开、定位等具名命令和桥接测试                                                |
| 独立下载页面与字典                      | 任务列表、来源输入、清晰度选择、真实进度和恢复操作；接入共享语言与外观                                                |
| 桌面状态样本、类型与 guard              | 同步新增下载状态字段，Rust/TypeScript 对同一份快照验证                                                                |

下载任务使用自己的标识、状态和历史，不借用设备发送的 `waiting`、对端回执或云盘配额语义。历史文件仅保留非敏感元数据，按本机存储的原子写入与权限规则保存；完整签名 URL、匿名 Cookie 和密钥不写入明文历史、日志或界面快照。

后续若让助手发起这些下载，再用同一核心新增 `apps/mcp` 的具名工具与测试；届时单独确定桌面与助手之间的本机任务协调，不能让两个进程各自改同一任务文件。本次先交付桌面入口。

## 文件、网络和进程边界

- 下载目录只能来自系统默认位置或系统选择器；文件名按 `assemble-device` 收敛；重名自动编号。完成前暂存、检查后发布，取消、失败或合并出错不留下冒充成品的文件。
- 现有 `assemble-transfer::staged` 在不支持硬链接时有“先检查再 rename”的回退，源码已注明竞态。新下载发布不能把该回退当作严格无覆盖保证：先确定可验证的跨平台无覆盖发布方式；不具备该能力的目录明确失败。将非硬链接文件系统和并发重名列入验收。
- 上游声明的长度和字节范围按实际内容核对；有可信来源摘要时必须校验。没有来源摘要时，内部计算的 SHA-256 只能用于本机完整性记录，不能冒充来源提供的摘要。最终媒体检查包括真实容器和音视频流，错误网页不能发布为视频。[FFprobe 文档](https://ffmpeg.org/ffprobe.html)
- 对入口、短链、重定向、子清单、分片和密钥统一执行 URL/协议/公网目标检查、DNS 连接绑定与大小限制；只允许预期的 HTTP(S)，不接受来源中的 `file:`、任意命令或本机路径。可选的来源网页地址仅用于受控 Referer，不提供任意 Cookie/请求头输入框。
- URL 可能带签名参数，不能回写到界面任务状态或持久日志；用户提交后界面保留任务标识和脱敏来源即可。需要保留的敏感来源材料只由 Rust 使用受保护存储处理。
- FFmpeg 只接收受控参数数组和可信本地输入，不通过 shell 拼接命令；其网络协议不开放。限制子进程输出与执行时间，原始工具诊断不回显给用户。

## FFmpeg 与安装包

本机已发现 `D:\ffmpeg\bin\ffmpeg.exe`、`ffprobe.exe`，可用于开发验证。正式安装包建议分平台捆绑固定版本的 FFmpeg/FFprobe，并核验来源和 SHA-256、保留许可证信息；用户无需自己配置 PATH。这会增加安装包体积，具体大小在构建样包后记录。

Tauri 支持随包携带分平台外部程序。运行仍只由 Rust 侧控制，不给前端开放通用 shell 执行权限。[Tauri 外部程序打包文档](https://v2.tauri.app/develop/sidecar/)

## 实施顺序

1. **先验证两条技术路线。** 用真实 FFmpeg 生成本地 HLS 测试媒体，验证 TS/fMP4、音画、AES-128、字节范围与本地合并；使用当前可公开访问的抖音样本验证 Jarvis 的两条解析路径在当前网络是否成立。同时验证 Windows/macOS 工具打包和无覆盖发布策略。先过这些检查，再接完整页面。
2. **实现独立 Rust 下载核心。** 完成来源 adapter、网络边界、任务队列、取消/重试、暂存发布与历史；注入测试网络和进程适配器。这个阶段避免编辑正在由其他会话修改的 UI 文件。
3. **接入桌面窗口。** 新页面和独立字典先写；菜单、App、状态、命令与桥接按小范围接入，接入前重新核对同工作区的最新改动，保留现有上传进度、布局、语言与外观行为。
4. **完成交付验证。** 运行全仓 `bun run verify`，真实构建并启动桌面应用，Windows 与 macOS 分别验下载、取消、重试、重名、中文文件名和退出清理；再用真实来源完成“能播放、有声音、确实保存成功”的验收。提交、推送、安装和发布分别记录，不互相替代。

## 验收标准

- 用户从“网络文件下载”完成一条 M3U8 和一条抖音视频，生成的文件格式真实、音画符合来源，进度与实际操作一致。
- M3U8 主清单选择、相对地址、初始化片段、字节范围、独立音轨和普通 AES-128 均有可重复夹具；缺失分片、长度不符、伪媒体、过期链接与网络中断明确失败，不发布残缺成品。
- 取消后请求和 FFmpeg 都停止；真正退出后无残留下载子进程；重启能区分历史完成和任务中断。
- 同名文件不覆盖；目录替换、路径越界、磁盘不足和不支持的发布方式均安全失败。
- 源地址/查询签名/匿名会话/密钥/内部诊断不进入界面快照、持久日志或普通历史；文件名等用户内容不被翻译或修改。
- 中文/English、浅色/深色/跟随系统、窄窗口与键盘操作保持现有共享组件约定；语言切换不重启下载或清空用户输入。
