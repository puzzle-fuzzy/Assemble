# N2 云盘文件夹实施计划

- 日期：2026-11-27。
- 状态：N2 源码及本地验收已完成，纳入全工作区汇总提交；尚未部署或发布桌面更新，Mac 与两台真实桌面验收待做。实际契约和验证记录见[文件夹手册](../runbooks/drive-folders.md)。承接[云盘增强总计划](2026-11-27-file-center-and-static-publishing.md)；N1 服务端与管理端已部署至 `ef808271dafc`。
- 本包只做云端目录组织：新建、进入、改名、移动文件与文件夹、删除空文件夹。管理员只读浏览，助手使用具名工具；不处理 iOS、APNs、推送、自动同步、目录批量上传、回收站、分享或静态托管。

## 当前实现与兼容边界

实施前经 CodeGraph 导航与源码确认，既有 `assemble-protocol::drive`、`drive::list` 和 `Client::drive` 为平铺契约。本次保留这些入口，另增 `drive_tree`。上传仍在落盘后通过 `BEGIN IMMEDIATE` 复核目录、配额与身份，再增加 blob 引用并建立文件记录；文件夹不是第二个内容引用者。

管理端保留全站文件分页列表，增加按账户只读浏览目录；桌面快照新增独立 `driveTree`，具名命令、桥接与类型守卫一起更新。目录层级来自服务端所属关系，不按文件名拼接。

现有 `/v1/drive/files` 的名单、上传、改名、下载与删除语义保留：旧客户端继续读取本人平铺名单，旧上传落到根目录，原文件标识与下载地址不变。旧的 `DriveFile/DriveListing` 线路类型不强制增加字段，也不要求改动 `apps/ios` 或它的样本。

目录能力使用独立的新入口和类型。新客户端连接旧服务时明确回退平铺模式、隐藏目录动作；不能让旧服务忽略一个新目录参数后，把文件悄悄上传到根目录。

## 用户界面

1. 工具栏在“上传”旁放同级小按钮“新建文件夹”，名称在弹窗中输入。表单使用 placeholder 与可访问名称，系统文案同时维护中英文。
2. 顶部面包屑表达“云盘 → 文件夹 → 子文件夹”，父级可以点击。内容区不重复放标题、说明或返回按钮；切换后聚焦当前位置，保留各目录的搜索与页码。
3. 文件夹排在文件前，名称可进入；文件继续使用 N1 预览与下载。内容列表沿用共享表格样式，管理端默认 20 条，桌面沿用共享表格默认值。
4. “移动”打开目录选择弹窗，以面包屑和当前层列表定位目标，明确确认后才写入。操作只传标识与版本，不传拼接路径。
5. 搜索只匹配当前目录的直接子项；清空使用输入框末尾的图标。空列表只显示必要文字，不加空状态图标。
6. 文件夹只允许删除空目录，非空时拒绝，避免把子树永久删除。N3 再统一引入回收站及子树恢复。

移动只更改云端父目录关系，文件内容、摘要与本机源文件均不搬动。上传仍经系统选择器选择文件，不随本包开放本机目录访问。

## 数据与规则

- 新增账户所属目录记录：标识、父目录、名称、版本、真实创建及更新时间。根目录用空父标识表示，不为每个账户编造一条历史创建记录。
- 文件记录补充父目录与版本；已有文件保留原标识、名称、内容、创建时间和 blob 引用，全部位于根目录。历史更新时间未知时保持 null，首次实际改名或移动时再记录。
- 版本号只用于并发校验，不保存文件的历史内容，不把本包扩大为文件版本管理。
- 同级文件夹名称唯一，包括根目录；名称复用单段名称校验，拒绝路径分隔符、控制字符、`.` 与 `..`。文件维持允许同名的现有规则，文件与文件夹按类型和标识区分。
- 初始硬上限建议为每账户 1000 个文件夹、深度 16 层，请求每页 1～100 条、搜索最多 200 字符；落地为协议常量并覆盖边界测试。目录本身不增加虚假的文件字节占用，数据库增长仍由现有存储监控反映。
- 新建、改名、移动与空目录删除逐次检查当前账户及版本，在写事务内再次检查父目录、祖先链、同级重名和深度。移动子树时同时计算其最深后代，不能只核对新父级的深度。
- 拒绝跨账户挂载、自身作为父级、进入自己的后代、根目录移动及非空删除。父目录和所属账户在数据库约束与业务事务两层保护。
- 上传在收正文前检查目标，建文件记录时再次检查目标仍存在、仍属于本人；目标被改名或移动不改变目录身份，已删除目标不得留下悬空文件。失败时复用未引用暂存内容清理。
- 改名和移动只改元数据，容量与引用数不变。旧入口的合法文件改名同样递增文件版本，让新客户端能够识别并发变化。
- 新建请求使用稳定请求标识；超时重试不重复建目录，相同标识不同参数拒绝。记录被删除后的重放不能悄悄重建；回执保留期限和上限随实现固定在协议规则中。

迁移编号以实际开工时的最新清单为准，不预占、不修改已提交脚本。若为所属关系约束需要重建文件表，必须精确复制原字段与索引，不能重新计数或释放 blob 引用；先在含旧数据的副本上验证。

## 提议契约

以下只约定新目录域的分工，尚不是已存在 API；实现时由 `assemble-protocol` 的类型与样本钉住，不在文档另造权威。

| 新入口                                                                 | 用途                                               |
| ---------------------------------------------------------------------- | -------------------------------------------------- |
| `GET /v1/drive/tree?parentId=root&q=&page=1&pageSize=20`               | 当前目录、有效祖先链、稳定分页子项、总数和账户容量 |
| `POST /v1/drive/tree/folders`                                          | 在明确父级新建文件夹，带稳定请求标识               |
| `POST /v1/drive/tree/files`                                            | 明确目标目录上传，复用长度、摘要、配额与无覆盖落盘 |
| `PATCH /v1/drive/tree/folders/{id}`、`PATCH /v1/drive/tree/files/{id}` | 带版本改名                                         |
| `POST /v1/drive/tree/moves`                                            | 带类型、标识、版本和目标父级移动一项               |
| `DELETE /v1/drive/tree/folders/{id}?version=`                          | 只删除空文件夹                                     |
| `DELETE /v1/drive/tree/files/{id}?version=`                            | 带版本删除文件，沿用现有引用释放；N3 再改为回收站  |
| `GET /v1/admin/drive/tree?accountId=&parentId=root&...`                | 管理员按所属账户只读浏览目录，不授予跨账户写权限   |

新列表使用带版本的目录/文件投影，文件投影复用已有必要字段，不暴露真实路径或新增授权 URL。根目录参数 `root` 是固定协议值；持久记录仍使用空父标识。分页按目录在前、创建时间和标识稳定排序；祖先链由服务端沿所属关系构造，不能相信客户端给出的面包屑。

目录不存在或不属于调用者统一按不可见处理；重名、版本冲突、循环、深度/数量超限使用独立稳定错误码。冲突时保留输入并让用户重新核对，不能覆盖最新状态。

桌面新增具名目录查询、新建、改名、移动及空目录删除命令，在 `commands.rs`、`bridge.ts`、handler 清单、快照和双语字典一起实现。管理员继续使用已验证邮箱、超级管理员与同源 HttpOnly 会话，不增加前端令牌。

MCP 补本人目录列表、新建、改名、移动与空目录删除；参数只有资源标识、版本、名称和查询，返回安全投影。空目录删除明确标注破坏性，不借此加入任意本机路径上传、下载或通用 HTTP 调用。

## 实施顺序与验收

1. **规则、契约与迁移。** 先实现父子关系、版本、名称、循环与深度检查，验证空库和现有数据升级；旧文件及所有 blob 引用逐项一致。
2. **服务端与客户端。** 接通目录查询、元数据写入和指定目录上传；将目标验证接入现有上传事务，复用下载和 N1 预览权限。管理端接口只读，旧入口保持兼容。
3. **桌面、管理端与助手。** 接通共享表格、弹窗和面包屑；保留现有刷新方式，写入后重取目录，不新增 iOS/推送事件。账户切换取消旧请求并清空旧目录路径、草稿和结果。
4. **回归与实际启动。** 覆盖根目录同名、跨账户、循环、子树深度、并发移动/删除、上传中目标删除、旧客户端改名、零字节及同摘要文件、搜索特殊字符和稳定分页。断言目录操作不改变文件摘要、引用计数或容量。

完整 `bun run verify` 后，在隔离服务上用两个账户实际完成建目录、上传、移动、重启、预览、下载及删除空目录，并核对字节与摘要。Windows WebView 与浏览器分别验收导航、焦点与关闭取消；Mac 实际行为单列。真实构建并启动镜像，部署前提交、检查三项 CI、备份、演练，再切换。

N2 通过后才实施 N3 回收站，届时统一处理删除子树、恢复原目录、目录冲突、回收站仍计入配额及永久清理引用；不在本包提前放入未完成的软删除分支。
