# 桌面个人数据：传输历史与云盘改名

## 传输历史

桌面应用数据目录内的 `transfers.json` 保存最近 100 条记录，按服务来源和账户隔离。文件采用 `assemble-store::json` 的私有写入与替换；其中可以保存本机收到文件的位置，快照与具名命令参数始终只使用记录标识。

退出应用再打开，已完成记录恢复，仍可“在文件夹中显示”。未完成任务显示“已中断”，不会自动重新读取上次选择的发送文件；有效收件与发送回执由服务端对账接回。草稿不恢复，避免发送已经变化的内容。

登录失效会隐藏记录，保留原账户历史供重新登录后恢复；用户明确退出登录并获服务端撤销确认后才清空历史。清空记录不删除收到的文件。遇到不可读、损坏或不支持版本的历史，保留原文件并报告本机存储错误，不当成空名单覆盖。

## 云盘改名

在云盘文件行点击“重命名”，输入新文件名并保存。校验沿用服务端协议，不能空白、包含路径分隔符或控制字符；允许同名文件。操作只改服务端名称，不移动或覆盖内容，标识、大小及原来的上传时间保持。

成功后以服务端完整名单更新界面；其他设备下次读取名单时可见新名称。文件已在另一台设备删除时，保留输入并显示固定错误；账户切换会中止旧请求，旧响应不写入新账户名单。

## 验收

- 自动化：历史纯规则、归属与损坏保护、重建应用状态后接收记录和文件定位；重命名命令参数、表单边界、失败重试、中英切换。
- 真人：完成一次收件，从托盘退出并重开，检查文件定位；改名后在另一台电脑读取确认。此流程须使用包含本轮实现的新安装包，不能用旧安装版的结果代替。
- 2026-11-27 用户确认 Windows 右键发送至另一台 Mac 成功，属于真实跨设备收发证据；它不代替这两项新增行为的验收，见[记录](../reports/2026-11-27-windows-to-macos-transfer.md)。

发布、安装与完整验证结果以本轮实施报告为准。
