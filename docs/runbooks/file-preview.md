# 云盘文件预览

桌面端与管理端的云盘文件行提供“预览”，打开共用 shadcn 弹窗；关闭后保留原列表、搜索、页码与触发按钮焦点。文件名与文本原文不翻译，系统文案同时维护简体中文和英语。无法预览或读取失败时保留原下载入口，不回显解码器和 Rust 的诊断。

## 支持范围与限制

| 内容            | 首批处理                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------- |
| JPEG、PNG、WebP | 检查实际格式并完整解码校验；文件最大 16 MiB，宽高分别不超过 8192，解码分配最多 64 MiB             |
| UTF-8 文本      | 最多前 1 MiB，截断保留完整字符并说明限制；包括 HTML、SVG 源文在内一律作为纯文本，不执行或嵌入页面 |
| 音频            | MP3、PCM WAV、MP4/WebM 中允许的音频轨道，由浏览器或 WebView 原生播放                              |
| 视频            | MP4/WebM 中的 H.264、VP8、VP9、AV1；音频轨道仅接受 AAC、MP3、Opus、Vorbis 及列出的 PCM 类型       |
| 其他            | 显示无法预览，用户仍可下载后使用本机程序查看；不嵌入 PDF/Office、不转码、不生成缩略图             |

实际能否播放仍取决于操作系统与浏览器的解码支持；原生播放器加载失败时展示统一提示与重试。图片、音视频不自动播放，使用原生播放和进度控件，不增加自制控制条。

服务端不相信扩展名和上传 MIME。图片由 `image` 校验；音视频由受限 `ffprobe` 检查容器与轨道，禁用网络协议，探测最多 6 秒、标准输出最多 64 KiB、最多 16 条轨道。全服务最多并行两次类型检查，只缓存 128 条格式描述、5 分钟，不缓存文本和授权。服务端镜像包含 `ffmpeg`（提供 `ffprobe`）；直接运行服务端时需将 `ffprobe` 放入 PATH，缺失时音视频如实返回不支持，不影响上传和下载。

## API 与授权

设备使用 `GET /v1/drive/files/{id}/preview`，管理员使用 `GET /v1/admin/drive/files/{id}/preview`，返回 `assemble-protocol::preview::FilePreview`：

```json
{
  "kind": "text",
  "mimeType": "text/plain; charset=utf-8",
  "size": 12,
  "text": "文件原文",
  "truncated": false
}
```

`kind` 是 `image/text/audio/video/unsupported`；非文本的 `text` 为 null，不支持时 `mimeType` 为 null。描述不含路径、摘要、设备令牌、Cookie 或读取 URL。Rust/TypeScript 使用 `apps/desktop/contract/previews.json` 样本核对形状，原有快照不变。

图片与音视频通过对应描述路径后的 `/content` 获取，文本和不支持格式的内容入口返回 404。设备入口逐次检查所属账户；管理员逐次检查已验证邮箱、超级管理员、HttpOnly 网页会话与同源证明，设备令牌不能访问管理入口。同站其他子域、跨站和缺少来源证明的管理员请求拒绝读取。响应禁止缓存，保留 `nosniff`、`Cross-Origin-Resource-Policy: same-origin` 与限制性 CSP；只使用检测后的 MIME 和固定 `inline`。管理页面仅增加 `media-src 'self'`，不允许任意来源媒体。

所有内容请求重新读文件记录后才查格式缓存，文件删除或所属改变立即影响后续请求。Range 与条件读取沿用附件服务，缓存中的分类不能代替鉴权。

## 桌面生命周期

界面只有 `drive_preview_open(fileId, requestId)` 与 `drive_preview_close(requestId)` 两条具名命令。请求标识是取消关联值，不是授权凭据。打开后返回描述与专用 `assemble-preview` 入口，入口只接受已登录主窗口、当前文件、当前会话代次和当前弹窗代次；页面没有通用文件或 HTTP 能力。返回地址不含真实路径和凭据，复制地址不能获得独立授权。

Rust 向已配置的服务来源添加设备授权，拒绝重定向，逐项核对 206、Content-Range、长度与 MIME。音视频一次最多 4 MiB，图片最多 16 MiB，全应用最多并行两次读取。关闭或更换弹窗、退出、换账户和主窗口关闭时取消旧读取；过期结果不再发布。React 卸载时主动暂停媒体、移除 src 并重新加载空资源。旧弹窗清理不能关闭新弹窗。

助手新增只读 `assemble_drive_preview(id)`：只返回当前账户文件的格式与大小，不返回文本、内容、地址、摘要和凭据。它不上传、下载或执行文件内容。

## 验收

自动化覆盖实际图片与 WAV 的内容识别、伪造 MIME、损坏图片、UTF-8 截断、账户隔离、管理员来源与权限、删除后的缓存失效、严格 Range、取消、双语、焦点恢复、错误收敛以及 MCP 安全投影。

Windows 本机隔离 WebView 已实际显示 PNG、播放 PCM WAV 和 7.4 MiB 的 H.264/AAC MP4，并从开头拖动到约 20 秒继续播放。Chrome 管理端已实际显示图片与纯文本、播放同一视频并跳转至约 21 秒，核对无解码错误、关闭后恢复原行焦点以及不支持文件的下载入口。真实浏览器发现并修复了管理页面缺少同源媒体 CSP 的问题，自动化也守住这一项。

上述支持格式的播放使用临时服务、合成账户及合成文件，没有操作正式数据、钥匙串或已安装客户端。Docker 镜像实际构建、以 uid 10001 启动且健康检查通过，镜像内 ffprobe 能识别相同 MP4 的 H.264/AAC 轨道；管理壳与预览入口的 CSP、禁止缓存、未登录 401 已实际核对。macOS WebView 尚需在 Mac 上实际验收，不能以 Windows 或 Chrome 结果替代。
