# 远程控制

本批源码支持同账户 Windows 和 Mac 互相查看画面并操作。尚未部署到正式服务，也没有更新安装包；两台电脑需要对应的新客户端和新服务端。范围与实现见[决策 0017](../decisions/0017-remote-desktop-first-batch.md)。

## 使用

1. 两台电脑在 Assemble 登录同一个账户并保持在线。
2. 控制端打开侧栏“远程控制”，选择另一台电脑的“连接”。
3. 被控端主窗口显示控制方，点击“允许”或“拒绝”。批准前不会采集画面或操作键鼠。
4. 点击画面开始操作；按 Esc 释放键盘焦点。工具栏提供“发送 Esc”、显示器切换、全屏和“发送文件”；文件仍通过原有发送面板选择目标。
5. 中文或其他 Unicode 文字可用画面下方的输入框发送。它不读取剪贴板。
6. 双方均可结束连接。被控端提示在切换功能页后仍显示；控制端离开画面页会结束连接。关闭主窗口也会结束正在参与的远程会话。

Mac 需要为当前应用授予“屏幕与系统音频录制”（屏幕录制）及“辅助功能”权限，修改授权后按系统要求重启。Windows 使用当前用户的桌面，无法控制锁屏、UAC 安全桌面和权限更高的窗口；屏幕/输入失败会关闭会话。睡眠、断网和设备撤销后重新发起并批准。

画面使用 JPEG 和已有 HTTPS 服务端中转，只保留最新一帧，适合基础桌面操作；实际帧率由编码与网络决定。未实现 H.264/30 FPS、音频、剪贴板同步、直连、无人值守、手机远程或断线自动恢复。当前服务端可见画面与输入，尚未实现端到端加密。不要把它描述成与 DeskLink 的全部能力一致。

## 本机验证

```sh
bun run verify
cargo test -p assemble-server --test remote
cargo run -p assemble-remote --features native --example capture
cargo run -p assemble-desktop --example remote-relay
```

`capture` 实际调用屏幕采集与输入能力的初始化；`remote-relay` 再把真实采集的一帧送入一次性本地服务端，由另一设备身份取回并逐字核对，再确认释放输入和结束。它们只输出画面尺寸、显示器数和编码后大小，不保存截图、不移动鼠标或键入；Mac 可能请求系统授权。服务端测试使用一次性本地库和测试账号，不操作正式账号。

2026-11-27 已验证：完整 `bun run verify` 全部通过（442 项界面与脚本测试、6 项仅 Mac 可运行的检查跳过；Rust 静态检查、Windows 目标含远程原生适配的检查与全部 Rust 测试通过）。真实本地 HTTP 的三条远程集成测试、输入队列/生命周期/按键/日志过滤及超时规则均通过。Windows 原生采集识别两个显示器，主屏缩至 1600×900；采集→本地中转→另一设备身份取回→释放输入→结束的完整探针通过，结果为 `native_relay_ok`。隔离桌面应用实际启动、打开远程页和未登录保护已核对，已有安装中的应用与正式账号未改动。这些不替代两台真实设备的验收。

本地证据（不进版本库）：`data/local/remote-verify-final.log`、`data/local/remote-capture.log`、`data/local/remote-relay.log`，以及 `data/local/remote-launch/` 的隔离启动日志。测试窗口和本地服务已经清理；完整真人登录、托盘退出、Mac 权限和实际远端键鼠操作仍未验收。

## 双机验收清单

- Windows→Mac、Mac→Windows 各完成申请、允许、出画面、停止；拒绝后没有画面和输入。
- 单击、双击、右键、拖动、滚轮；Ctrl/Shift 与鼠标组合；中文输入与常用快捷键。
- 两端分别切换显示器，核对缩放和负坐标显示器的指针位置；全屏、Esc 返回和窗口缩放。
- 控制端切页、失焦、断网、退出；被控端停止、退出、睡眠、撤销设备，均没有遗留按键。
- Mac 实际权限拒绝与恢复，Windows 高权限窗口、锁屏和 UAC 均不会越权操作。
- 远程期间从发送面板选择对应电脑发文件，核对摘要与原有接收位置。

上述双机、Mac 权限与真实远端输入仍待验收。没有正式部署、跨网性能或长期运行证据。
