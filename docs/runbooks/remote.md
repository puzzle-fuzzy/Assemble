# 远程控制

本批源码支持同账户 Windows 和 Mac 互相查看画面并操作。尚未部署到正式服务，也没有更新安装包；两台电脑需要对应的新客户端和新服务端。范围与实现见[决策 0017](../decisions/0017-remote-desktop-first-batch.md)。

## 使用

1. 两台电脑在 Assemble 登录同一个账户并保持在线。
2. 控制端打开侧栏“远程控制”，选择另一台电脑的“连接”。
3. 两端显示核对代码，逐组核对一致后，被控端点击“允许”。不一致则拒绝并重新申请；握手完成前不能允许，批准前不采集画面或操作键鼠。
4. 点击画面开始操作；Esc 释放焦点。工具栏提供画质、显示器、适应/1:1、拖动浏览、全屏、“发送 Esc”和文件入口；浏览模式只移动本地视图，Esc 返回控制。全屏隐藏应用侧栏，鼠标移到顶部或键盘聚焦可唤回工具栏。
5. Unicode 文字可在画面下方输入；纯文本剪贴板通过“发送剪贴板”“取回剪贴板”或 Ctrl/Command+V 主动交换。上限 48 KiB，不自动读取，正文不进界面。Ctrl/Command+V 会先传到远端剪贴板再执行粘贴。超时/失败请先检查远端状态，避免重复粘贴。
6. 声音默认关闭，点击开启系统声音；再次点击立即静音。只读取系统输出，不选择麦克风。设备或权限不可用时有提示，画面仍可继续。
7. 双方均可结束连接。被控端提示在切换功能页后仍显示；控制端离开画面页会结束连接。关闭主窗口也会结束正在参与的远程会话。

Mac 需要为当前应用授予“屏幕与系统音频录制”（屏幕录制）及“辅助功能”权限，修改授权后按系统要求重启。Windows 使用当前用户的桌面，无法控制锁屏、UAC 安全桌面和权限更高的窗口；屏幕/输入失败会关闭会话。睡眠、断网和设备撤销后重新发起并批准。

画面优先使用 H.264 软件编码/WebCodecs 解码，不支持时回退 JPEG；实际帧率受采集、软件编码与网络影响，尚无 30 FPS 或硬件编码验收。自动画质会随处理耗时降升档，手动画质由被控端执行后确认。服务端只保留有界密文，远程画面、键鼠、剪贴板、声音由 Rust 侧 Noise 加密；必须实际核对代码才能确认对端，不能跳过核对再宣称身份已认证。现有文件/云盘仍走原管线，不因远控加密而变成端到端加密。按用户确认，本次不加入跨账户、直连、无人值守、免确认重连或手机远控。光标仅同步位置，尚无原生光标形状同步。

输入与画面上传分别运行，慢网传画面时仍可处理键鼠；静止且显示器元数据未变时不重复上传同一张 JPEG。被控端拒绝、请求过期、对方结束、断网、撤销设备及原生故障有各自提示。停止会丢弃排队输入，先完成本机释放，再通知服务端；此前松键失败的项目会保留跟踪，在退出清理时再尝试，最终释放失败记录固定错误日志。

## 本机验证

macOS 构建需要 Xcode 26.3 或更高版本：ScreenCaptureKit 11 的必需传递依赖 `apple-metal` 的 Swift 桥接包含 macOS 26 SDK 符号，即使只使用系统音频也会编译它，不能靠关闭可选功能移除。验证与安装包任务在 `macos-15` 上显式选择 Xcode 26.3；[运行器清单](https://github.com/actions/runner-images/blob/main/images/macos/macos-15-Readme.md)中默认仍是 16.4。构建 SDK 与最低运行版本不同，应用最低运行版本仍为 macOS 13；旧系统与系统音频仍需真机验收。

Windows 目标检查由 `scripts/verify/windows.ts` 按宿主选择范围：六个基础库的规则在 Mac 也检查；带 H.264/Opus 本机 C/C++ 依赖的原生适配只在 Windows 启用。两平台的主验证仍分别检查和测试各自完整的原生实现，不能用 Mac 上的纯规则交叉检查替代 Windows CI。

```sh
bun run verify
cargo test -p assemble-server --test remote
cargo run -p assemble-remote --features native --example capture
cargo run -p assemble-remote --features native --example capture -- --video --audio
cargo run -p assemble-desktop --example remote-relay
cargo run -p assemble-desktop --example remote-relay -- --video
```

`capture` 采集真实屏幕，`--video` 再解码 H.264 核对尺寸；`--audio` 明确采集一小段系统输出并验证 Opus 解码，不播放、不保存声音。`remote-relay` 以测试身份三步握手并批准，将真实画面加密送到一次性本地服务端，由另一设备取回核对完整帧摘要，然后确认释放输入与结束；`--video` 要求取到关键帧。探针只打印有限元数据，不保存截图、不移动鼠标、不键入、不改剪贴板；Mac 可能请求系统授权。测试账户和数据库都在本机，不操作正式账号。

2026-11-27 这一轮新增真实 HTTP 密文握手、篡改/截断拒绝、音频与剪贴板方向/期限/清理测试，以及视频参考链恢复、心跳防重放、旧屏输入隔离和音频非致命事件回归。Windows 原生探针识别两块屏幕，H.264 流畅档 1000×562 编解码成功，系统声音得到 5 个有效 Opus 包并解码成功；H.264 均衡档 1600×900 经本地加密中转取回，完整摘要相同，释放输入和结束均成功。该探针不测真实跨网带宽或帧率，也不替代实际远端输入或真人核对代码。

完整 `bun run verify` 于 2026-11-27 全部通过，用时 168.9 秒，包含格式、类型、界面/工具测试、全部前端构建、Rust 与 Windows 目标静态检查和全仓 Rust 测试。发布清单测试曾遇到一次 Windows 临时文件重命名 `EPERM`，单独复测及随后整仓重跑均通过，未更改发布规则。

本轮还实际启动了隔离服务端（`/healthz` 正常）和 Tauri 桌面窗口，核对远程页与未登录保护，并清理测试进程。本地证据（不进版本库）：`data/local/remote-complete-verify-final.log`、`data/local/remote-complete-native-media.log`、`data/local/remote-complete-relay-video.log`、`data/local/remote-complete-server-launch.log`、`data/local/remote-complete-desktop-launch.log`。Mac 原生音频需要在 Mac 上编译和运行；完整真人登录、托盘退出、权限与真实远端输入仍待验收。正式服务、已有安装和正式账号不变。

## 双机验收清单

- Windows→Mac、Mac→Windows 各完成申请、允许、出画面、停止；拒绝后没有画面和输入。
- 每次实际核对两端代码，一致再批准；拒绝不一致代码，断线后新会话必须重新核对和批准。
- 单击、双击、右键、拖动、滚轮；Ctrl/Shift 与鼠标组合；中文输入与常用快捷键。
- 两端分别切换显示器，核对缩放和负坐标显示器的指针位置；全屏、Esc 返回和窗口缩放。
- H.264/JPEG 回退、画质切换、丢帧恢复，1:1/拖动浏览时无远端输入；屏幕拔出仍保持可用当前屏。
- 双向纯文本剪贴板、中文、超限与超时，确认不会重复粘贴；Mac Command+V 与 Windows Ctrl+V 分别验证。
- Windows 与 Mac 系统声音开/关、静音后无残留播放、设备切换、权限失败，以及音画延迟；始终不采麦克风。
- 控制端切页、失焦、断网、退出；被控端停止、退出、睡眠、撤销设备，均没有遗留按键。
- Mac 实际权限拒绝与恢复，Windows 高权限窗口、锁屏和 UAC 均不会越权操作。
- 远程期间从发送面板选择对应电脑发文件，核对摘要与原有接收位置。

上述双机、Mac 权限与真实远端输入仍待验收。没有正式部署、跨网性能或长期运行证据。
