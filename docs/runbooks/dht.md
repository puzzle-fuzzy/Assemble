# DHT 管理端

入口是网页 `/admin/#dht`。只有已验证邮箱的超级管理员可以访问数据，普通用户与设备令牌均无权限。历史数据未导入，两个旧仓库与服务不受本次本地功能迁移影响。

## 使用

列表支持名称或 Info-hash 搜索、解析状态与证据来源筛选、服务端分页、详情中的文件清单及磁力复制。按用户 2026-11-26 的要求，默认选中“已验证”，只显示已经解析成功并通过摘要校验的记录；可手动切换到“全部”查看其它状态。复制失败时可以从详情中的磁力文本手动复制。元数据中的文字按普通文本展示。

“查询哈希”接受 40 位十六进制、32 位 Base32 或包含 `xt=urn:btih:` 的磁力链接；它不会增加 announce 或采样次数。每条记录的解析最多尝试三轮，每轮至多三个公网 Peer；管理员重试遵守一分钟冷却与同一队列上限，已经验证或正在排队的记录不会重复领取。

Announce 和采样只是本节点看见的事件，不是下载次数或全网热度。文件清单来自经过摘要校验的 info 字典，不是已下载的内容。诊断中的解析成功只在数据库成功发布后增加，当前进程计数重启归零，列表总量与状态数保留。

运行操作：

| 操作     | 效果                                                         |
| -------- | ------------------------------------------------------------ |
| 开始采集 | 加入 DHT，接收真实 announce，主动采样并解析                  |
| 暂停采集 | 停止新观测与采样，继续 Peer 查询与已有任务，逐批提升暂缓任务 |
| 停止 DHT | 取消 UDP、解析连接和在途任务，释放监听端口，保留队列与数据   |

运行模式在库里保存；进程重启后恢复。服务启动或停止时会回收遗留 `fetching`，已用的尝试次数保留。按用户 2026-11-26 的反馈，页面、详情和采集启停均不再定时轮询；需要最新数据时手动点击刷新或重新载入页面。搜索、筛选、翻页和提交查询仍按操作请求数据，关闭详情会取消旧请求。

同次反馈要求由布局表达用途，移除常驻的辅助说明。当前采集模式使用表格右侧工具栏中的按钮，展开后提供开始、暂停与停止；相邻图标按钮按需打开运行详情，统计与容量信息不再独占页面行。列表解析状态也使用同尺寸的共享按钮，支持悬停与键盘焦点，点击打开种子详情。

## 启用配置

配置只在服务端读取，页面不接受任意地址、外部解析器或文件路径。

| 环境变量                     | 默认值         | 说明                                                 |
| ---------------------------- | -------------- | ---------------------------------------------------- |
| `ASSEMBLE_DHT_ENABLED`       | `false`        | 允许 DHT 运行，首次仍为停止状态                      |
| `ASSEMBLE_DHT_LISTEN`        | `0.0.0.0:6882` | IPv4 UDP 监听地址，端口不可为零                      |
| `ASSEMBLE_DHT_MAX_RECORDS`   | `100000`       | 接受 1000～1000000，重复观测可更新，新增记录不能超限 |
| `ASSEMBLE_DHT_PEER_EXCHANGE` | `false`        | 开启有界被动 PEX 提示，不提高解析并发                |

固定预算：16 个并发 DHT RPC、5000 个路由节点、每 5 秒最多一次采样，并尊重远端不超过 6 小时的刷新间隔；2000 条解析队列、4 个解析任务、单 Peer 总期限 15 秒、每轮总期限 45 秒、8 MiB info 元数据、50000 个文件、64 层 bencode 容器。文件清单在库中最多使用 512 MiB，达到上限停止领取，不绕过预算发布。

Peer 与节点地址都经过公网检查，不解析 Peer 提供的主机名，不访问私网与回环地址。直接 announce 的候选地址最多按 2000 个哈希各保留 3 个，保留一分钟，仅供随后领取的任务使用。库、API、日志和状态中没有候选地址。

## 部署前另行处理

当前默认部署只映射 HTTP，没有 DHT UDP 入口。正式启用前需确认服务器上 6882 未被占用，并单独批准容器 UDP 映射、安全组/防火墙调整。HTTP 管理端继续使用现有反向代理，不为 DHT 新增 nginx 站点。旧服务的 UDP 6881 不改动。

2026-11-26 用户随后明确授权提交全部代码、合并主分支、推送、全量部署并开启公网采集。这包含本服务所需的 UDP 映射与该端口的放行，不扩大到其它站点或旧 DHT 服务。

公网部署显式叠加 `deploy/compose.dht.yaml`；已有密钥挂载要保留，部署目录的 `COMPOSE_FILE` 使用 `compose.yaml:compose.secrets.yaml:compose.dht.yaml`。新增端口默认是 IPv4 UDP 6882；本机容器验收可用 `ASSEMBLE_DHT_HOST_IP=127.0.0.1` 限制在回环地址。

启用后通过具名运维命令控制，不直接修改数据库、不获取用户网页会话：

```sh
docker compose exec -T assemble assemble-server dht-mode collecting
docker compose exec -T assemble assemble-server dht-status
docker compose exec -T assemble assemble-server dht-mode draining
docker compose exec -T assemble assemble-server dht-mode stopped
```

模式变更和网页共用同一事务审计；重复设置不重复记账。命令返回配置是否启用、持久模式和数据库聚合计数，不返回 Peer、节点或登录凭据。输出模式表示已持久接受请求，实际网络状态还须通过监听端口与后续入库核对。

部署使用原来的镜像与 `deploy/push-image.sh`，遵守 [部署手册](deploy.md)。数据在同一份 Assemble SQLite 中，备份必须包含数据库及 WAL 的一致快照；不能只备份 blobs。回滚旧二进制前先评估新迁移，不能通过修改或删掉已经应用的迁移来回滚。

## 验证

- `bun run verify` 覆盖界面、双语键、契约样本、Rust 协议与服务端集成。
- `cargo test -p assemble-dht` 用回环 TCP/UDP 验证帧、摘要、token、伪造响应拒绝和退出释放；这些测试不访问公网 DHT。
- `cargo test -p assemble-server --test dht` 用临时数据库与真实回环服务验证权限、队列、搜索、控制和显式退出，引导节点为空，不访问公网。
- 浏览器视觉验收使用隔离的合成数据，不能当作公网发现与元数据吞吐的证据。

真实公网采集仍需在目标服务器确认 UDP 可达、观察数据库中新增的 `verified` 与样本证据，并检查 CPU、内存、磁盘和错误计数。旧实验的吞吐不能作为 Assemble 的基准。
