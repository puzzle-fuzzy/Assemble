# 私人文本备忘录

2026-11-26 用户要求新增备忘录：桌面端普通用户新建或粘贴纯文本，列表中直接复制。用户进一步确认每个账户独立保存，切回原账号时恢复该账号内容。当前源码已接入，发布与真人验收单列，不代表正式环境已更新。

## 使用

桌面侧栏进入“备忘录”。登录后可搜索标题或正文、按页查看，并新建、编辑、查看和删除；详情、编辑和删除确认均使用弹窗。每行的“复制”直接复制完整正文，保留空格、制表符和换行，不包含标题或表格摘要。文本不解释为 HTML，不支持图片、附件或富文本。

标题最多 200 个 UTF-16 单元，正文最多 100,000 个 UTF-16 单元；表情可能占两个单元。空白正文与不适合文本的控制字符会被拒绝。标题去除首尾空白，正文原样保存。复制失败有可见提示，详情中的只读文本框也可手动选取原文。

切换、退出账户立即卸载当前备忘录和草稿，旧请求不得恢复内容或迟到写入剪贴板；切回原账户重新从服务端读取已保存的备忘录。页面重新进入或点击刷新可获取其他设备的改动，首批不提供离线编辑或实时推送。

## 存储与权限

数据位于服务端 SQLite，通过新增 `0009_memos.sql` 迁移创建 `memos` 与 `memo_requests`。备份包含整个数据库；不是浏览器本地存储，也不是桌面公共文本文件。列表只返回前 200 个字符的摘要；完整正文逐条读取，响应禁止缓存。没有管理端代看入口或公开分享。

`GET/POST /v1/memos` 与 `GET/PUT/DELETE /v1/memos/{id}` 只接受设备身份，并以其所属账户约束查询。网页 Cookie 不获得该能力。写事务内再次检查设备存在、账户归属与停用状态；他人标识与不存在均返回 404。修改和删除带版本号，冲突返回 `VERSION_CONFLICT`，不会覆盖别处改动。

新建带稳定 `requestId`，同一次失败重试不重复创建；复用键提交不同正文会拒绝。删除后保留新建回执，旧请求的重试不能复活已删除的备忘录。JSON 正文上限 512 KiB；分页参数与搜索长度在协议层共同校验。

前端只调用 `memo_list/get/create/update/remove/copy` 六个具名命令。复制只把标识交给 Rust，Rust 重新鉴权取得原文，并检查会话分界后才写系统剪贴板；没有开放通用网络、文件或任意剪贴板写入权限。凭据、请求摘要和服务器路径不进入前端或日志。独立响应样本在 `apps/desktop/contract/memos.json`，Rust 与 TypeScript 共同核对；主 Snapshot 结构不因备忘录增加字段。

按具名工具约定，MCP 同步提供 `assemble_memos`、`assemble_memo_get/create/update/delete`，仅访问助手当前登录账户。新建必须带稳定请求键，修改与删除需带当前版本；没有远程剪贴板工具。

界面中英资源与外观沿用共享 display/ui，日期按本机时区显示，语言切换不更改文本、时区或草稿。
