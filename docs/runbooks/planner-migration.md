# Jarvis 日程迁移

用户 2026-11-27 明确授权迁入线上日程、提醒及附属个人记忆和偏好；源仓库、源库和源站仍然只读。此命令不迁移账户、设备、认证、日志、文件或影视。个人资料只进入指定账户的私人备忘录，管理员接口不提供代看。

## 导出与预检

先按 Jarvis 当前受保护部署配置核对真实生产库，不把仓库里的测试库当成来源。脚本只读取指定账户的日程、提醒、相关通知、`personal.*` 偏好和地址登记表；来源任务/目标表另行盘点，本次为空，不虚构任务。

```sh
umask 077
bun scripts/planner/export-jarvis.ts <源数据库> <源账户ID> <全新导出目录>
assemble-server import-planner-archive <导出目录> --email <已验证目标邮箱>
```

导出使用只读 SQLite 连接和同一读事务。目录必须全新，包含 `archive.json` 与 `archive.sha256`；导出摘要只输出数量。预检不连接目标、不跑迁移，不会建立账户。真实来源包含个人资料，只放本机 `data/local/` 或服务器受限备份目录（目录 0700、文件 0600），不提交 Git。

## 导入

1. 核对目标邮箱、源账户和导出计数，保存目标库的一致 SQLite 备份与既有日程摘要。备份在受限目录中保留，不把旧备份覆盖回已经接受新写入的正式服务。
2. 在隔离测试库演练，验证导入前后字段、原文、UTC 时间、版本与创建/修改时间一致，目标原有记录完整保留。
3. 部署包含新迁移和维护命令的已验证服务端；短暂停目标服务后，使用原受保护环境和数据卷执行：

```sh
assemble-server import-planner-archive <导出目录> --email <已验证目标邮箱> --apply
```

4. 启动服务，核对健康、账户隔离、导入数量与来源摘要，再执行一次确认 `alreadyImported=true`。来源在导出后变化时先重新核对，不能用新的来源静默覆盖已迁入后的用户修改。

导入使用写事务。目标必须已验证且未停用；编号以来源、目标账户、资源及源编号稳定生成，冲突整批回滚；不会覆盖既有日程或备忘录。来源原文和时区留在账户所属的导入回执中，日程/提醒保存原始绝对时间。重复导入不重建用户后来编辑或删除的记录。

## 地址与显示

单个地点及 `navigation.locations.v1` 中与当前来源版本匹配的绑定一同迁入；过期绑定只保留在来源回执，不投影到当前正文。标题、备注、备忘录中的长地名优先匹配，原文 URL 保持完整，不从内容推测新地址。只组合共享 shadcn 链接按钮，不解释 HTML。

桌面通过 `open_record_location(resource,id,label)` 打开地图：Rust 向服务端重新读取本人记录，目标固定为 Jarvis 同款 `https://maps.apple.com/directions`，目的地作为一个编码参数。其他账户、被删除记录和已撤下绑定不可导航；修改正文会撤下旧补充绑定，仅改时间或状态仍保留。一次性远期安排可见，重复日程仍只展开七天。

数据库新增 `0013_planner_import.sql`；旧迁移不改。`Planner.navigation` 与 `Memo.locations` 是可选只读字段，空时省略，旧客户端仍可读取基本日程。桌面的完整地址能力需运行包含新命令的构建；旧安装版不会因仅更新服务端自动获得此界面。iOS 不在本次界面调整范围。

导入源里结束时间可精确到秒。桌面仍使用现有分钟选择器，但未改动的时间原样提交；仅改标题或备注不会抹掉秒和毫秒。
