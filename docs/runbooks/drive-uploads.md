# 云盘上传续传（N4.1）

源码与本地验收已完成，尚未正式部署或发布桌面签名更新。N4.1 处理当前桌面进程内的云盘上传；服务端重启或网络中断后，可以继续原会话并补传缺片。N4.2 已补充[本机恢复与下载续传](drive-recovery.md)，设备发送续传仍属后续 N4.3。本包未修改 iOS、APNs、推送、签名更新或助手工具。

## 用户操作

仍从云盘上传或发送面板选择云盘开始。原传输行提供暂停、继续和取消，图标按钮的可访问名称带完整文件名，中英同步。暂停保留已确认进度，自动重试不能唤醒；继续前重新核对源文件长度及摘要。源文件变化就停止，不拼接新旧内容。目标目录或任一祖先版本变化时明确停止并要求重新选择文件上传；首包不重新绑定旧会话，也不改存根目录。

取消停止本机请求，并用稳定请求键向服务端对账；临时网络故障会退避重试。完成已经先提交时按真实完成回执显示，不自动删除已登记文件。退出清理仍停止本机会话；N4.1 首包没有恢复队列；当前 N4.2 独立私有日志让已确认云盘任务在重开后先暂停，旧历史仍只标中断。未完成的服务端会话随后按期限回收。

只在新任务开始前探测能力。旧服务明确返回 404 时沿用完整上传，普通上传仍可用，探测完成后不出现暂停继续，也不在重开后自动重放旧完整请求；认证、网络错误不是“不支持”。已经创建的会话到期或位置冲突不能悄悄换旧入口重建文件。

## 协议与权限

权威 DTO 在 `assemble-protocol::uploads`，只由 Rust 客户端使用。界面快照新增 `paused`、`resumable` 和固定失败原因，不包含文件路径、摘要、稳定请求键或凭据。旧云盘文件、发送与 iOS 的线格式保持原样。

| 入口                                            | 作用                                       |
| ----------------------------------------------- | ------------------------------------------ |
| `GET /v1/drive/uploads`                         | 已认证设备探测布局与限额                   |
| `POST /v1/drive/uploads`                        | Create 初始化或重取同一会话                |
| `GET /v1/drive/uploads/{id}`                    | 查询真实确认片及终态回执                   |
| `PUT /v1/drive/uploads/{id}/parts/{index}`      | 二进制片，带 `x-content-sha256`            |
| `POST /v1/drive/uploads/{id}/complete`          | 校验、登记并返回唯一文件回执               |
| `DELETE /v1/drive/uploads/{id}`                 | 取消或返回已经完成的真实回执               |
| `DELETE /v1/drive/uploads/requests/{requestId}` | 初始化回执丢失或初始化迟到时，仍可稳定取消 |

Create 字段为 requestId、name、size、sha256、mimeType、parentId、location；location 是从根到当前目录的 `{id,version}` 数组（根自身省略）。Upload 为 id、phase（receiving/completed/cancelled/expired）、partBytes、parts（index/size/sha256）、expiresAt、file（TreeFile 或 null）。时间仍为协议 Timestamp。

资源标识不授予权限。每次请求绑定本人账户与原发起设备，另一台本人设备也不能写入或读出会话；停用、撤销仍即时拒绝。持久确认和最终登记再次核对身份。接口 no-store，不提供分片下载、跨账户内容存在性查询或按声明摘要秒传。初始化必须收到并校验全部内容，才能复用内容去重。

常见固定错误：UPLOAD_REQUEST_CONFLICT、UPLOAD_PART_CONFLICT、UPLOAD_TARGET_CHANGED、UPLOAD_INCOMPLETE、UPLOAD_LIMIT、UPLOAD_EXPIRED、UPLOAD_CANCELLED、UPLOAD_FINISHED；原 QUOTA_EXCEEDED、HASH_MISMATCH 保留。诊断文字不显示给用户。

## 边界与存储

- 单文件仍为 100,000,000 字节。固定 2 MiB，最多 48 片，零字节不需要片但仍核验空摘要并登记。片号决定长度，不开放任意范围；重复片重新校验声明和实际字节，幂等片不延长存活时间。
- 每设备 2、每账户 4、全站 32 个接收会话；同时最多 32 个片请求、2 个合并请求。账户最多保留 10,000 个稳定请求回执（含先取消的键），保留到账户删除；达到上限拒绝新建，已有完成和取消仍可读取。首包不自动删回执，避免旧请求复活。
- 连续 24 小时没有新片确认就过期，绝对最长 7 天。读取、相同片重试、失败请求不续期。每分钟维护将过期会话转终态、释放预留并继续持久暂存清理。
- 新迁移 `0017_drive_uploads.sql` 增加会话、确认片、统一上传预留和独立暂存清理表；已有迁移不改。暂存仅在数据目录的 `uploads/<服务端随机标识>/`，不接收用户路径。
- 分片先写临时文件、同步文件，再发布为固定片文件并记确认；未提交的同片遗留可安全重写。完成流式重验每片与整文件，再复用 BlobStore 的摘要租约。网络/文件 I/O 不占长期数据库写事务。短事务同时登记文件、内容引用、完成回执和清理任务。重试完成只返回原对象，不重复加引用。
- 配额包含活动和回收文件及未完成逻辑预留；全站预算包含内容及预留。已确认片不再额外扣一次预留。旧完整云盘上传和设备发送使用同一事务准入，登记排除自己的预留；已有内容的旧去重行为保留。旧完整请求最多一小时，遗留预留两小时后清理，正常成功或失败显式释放。
- 暂存、合并、内容库暂存有实际磁盘峰值；开始、接片与合并前检查磁盘余量，存储失败不会发布坏内容。取消释放逻辑预留，实际暂存删除失败则保留清理任务和字节，首次失败审计一次，重启继续。账户删除后的孤立目录只在这个受控命名空间清扫。

管理存储监控新增 uploadReservedBytes 与 uploadTempBytes（无法测量为 null），旧服务缺字段显示未知。预算预警同时计入预留，暂存容量按分片会话目录内实际文件测量（不含 BlobStore 正在写入的瞬时暂存），不把它再次加入同一预算；磁盘可用量仍独立实测。管理员不代用户操作任务。

## 验证与发布

真实临时服务测试覆盖回执丢失、重启补片、重复与坏片、零字节、会话限额、并发配额、位置变化、源变化、取消与完成竞态、旧接口准入及清理失败重启。原生任务测试覆盖暂停不唤醒、继续保留片、稳定取消与退出后的迟到结果；共享快照、具名桥接和双语按钮另有界面测试。

发布先服务端、后签名桌面更新。N4.1 正式发布和各平台实际验收以部署记录及本机 `data/local/n4/acceptance.md` 为准，代码、自动化、窗口验收和正式上线分别记录。备份须包含同一时点数据库、blobs 与 uploads；不可只备份数据库就声称可以恢复在途上传。

本轮完整 `bun run verify` 通过，用时 218.6 秒：507 项 TS 通过、6 skipped；733 项 Rust 通过、2 项既有 ignored。真实 Linux 镜像以 uid 10001 启动，迁移 1～17；6,820,000 字节上传在确认第一片后停服、重启，仅补剩余片，重复完成与完成后取消均返回同一对象，下载逐字节一致。Windows 隔离 WebView 显示 33% 暂停行、完整文件名和具名图标，Rust 验收控制继续后原 6,291,467 字节一致且只建一个文件；Chrome 管理端读到两任务预留 12 MiB、实际片 4 MiB。没有使用真实密码或正式测试账户，没有发布或安装客户端。Mac WebView、双机及最大并发压力未验收，不以本机替代。
