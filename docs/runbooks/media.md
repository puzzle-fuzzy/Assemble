## 入口与权限

| 入口                 | 用途                                                         | 权限                                                   |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------ |
| `/admin/` 的影视片库 | 共享条目维护、来源导入、图集/封面、合集、统计                | 已登录、邮箱已验证且具有超级管理员权限的网页会话       |
| 桌面端的影视片库     | 共享列表与详情；本人私人片库维护                             | 共享可匿名读取，私人操作需要本人登录；没有共享管理入口 |
| `/movies/`           | 海报墙、详情、状态筛选、演员作品、合集与本人私人库的只读展示 | 共享匿名可读，磁力登录后可读，私人内容只给本人         |

共享与私人都支持想看、在看、已看。共享观后感公开，备注只给管理员；私人观后感和图片仅本人可读。匿名共享响应的 `magnetUri` 为 null，仅保留 `magnetAvailable`，不能依赖前端隐藏按钮来保护链接。合集只引用共享条目，统计只包含共享库。

管理员仍只在浏览器使用管理端，不安装管理桌面程序。设备令牌不允许访问管理 API，普通账户不能因首先注册而提权；初始化管理员见[管理端手册](admin.md)。2026-11-26 用户另行授权完整导入 Jarvis 线上影视、缓存、封面与旧影视归档；账号、认证关联与旧站点设置仍不迁移，源站保持只读。

2026-11-26 按用户要求，在有对应用户展示页的管理表格工具栏提供直达入口：共享片库“查看影视站”打开 `/movies/`，合集“查看合集页”打开 `/movies/collections`。链接用新标签页打开，保留当前管理端搜索和页码；展示站继续只读并复用本站会话。管理端开发服务器将 `/movies` 代理到本地 Rust 服务，需先构建展示站资源。

同日用户要求所有表格都保留拖拽柄、多选框列，即使对应能力禁用也不能省略。共享/私人条目与合集名单按服务端顺序展示，拖拽柄禁用；统计表两种控件均禁用。编辑合集时的成员表支持实际拖拽和 Alt 加上下方向键调整，并保留具名上移/下移按钮；仅更新当前草稿，点击保存后才通过已有版本核验写入成员顺序。拖拽过程中按 Escape 取消，调整后焦点留在被移动成员上。

## 服务端配置

| 变量                            | 用途                      | 默认与约束                                                       |
| ------------------------------- | ------------------------- | ---------------------------------------------------------------- |
| `ASSEMBLE_TMDB_TOKEN`           | TMDB 访问凭据             | 可选，仅受保护服务端环境；与 `_FILE` 二选一                      |
| `ASSEMBLE_TMDB_TOKEN_FILE`      | 从受保护文件读取同一凭据  | 可选，文件必须能由服务进程读取；不把文件内容回显到日志或检查结果 |
| `ASSEMBLE_MEDIA_WEB_ASSETS_DIR` | `/movies/` 的构建资源目录 | 本地 `apps/media-web/dist`；镜像 `/usr/share/assemble/movies`    |

用户已授权复用已有 TMDB 凭据，凭据只能复制到 Assemble 的受保护服务端配置。另行授权的影视数据由下文维护导入处理；导出包、缓存原文、归档及数据库备份均属运维数据，不进入 Git。不要将 Jarvis 的真实邮箱、旧域名配置或密钥值复制进本仓库，不修改只读参考仓库；“已准备文件”也不能写成“正式已启用”。

推荐文件模式。沿用现有 `compose.secrets.yaml`：宿主机 `deploy/secrets/` 对应容器 `/run/assemble-secrets/`，目录与文件属于 uid/gid 10001，权限分别为 0700/0400。只在受保护 `.env` 中记录路径：

```dotenv
ASSEMBLE_TMDB_TOKEN_FILE=/run/assemble-secrets/tmdb-token
```

密钥由部署操作者在受保护文件中放好，不通过命令参数、聊天或终端输出传递。文件模式启动仍需叠加现有挂载：

```sh
docker compose -f compose.yaml -f compose.secrets.yaml config --quiet
docker compose -f compose.yaml -f compose.secrets.yaml up -d
```

不要同时设置 `ASSEMBLE_TMDB_TOKEN` 与 `ASSEMBLE_TMDB_TOKEN_FILE`。未配置 TMDB 时接口明确报告来源未配置；豆瓣使用公开来源，不读取私人 Cookie、不提供绕过验证的手段。`/v1/media/capabilities` 的来源标记只说明已配置或有适配器，不能证明当前出口和外部来源可访问。

## 本地开发

```sh
bun run admin:dev      # http://127.0.0.1:1421/admin/
bun run media:dev      # http://127.0.0.1:1422/movies/
bun run server:dev     # http://127.0.0.1:8787，使用独立本地数据
bun run dev            # 桌面端，只经 Rust 具名命令访问服务
```

要核对服务端实际托管而非 Vite 的页面，先构建，再启动服务端：

```sh
bun run admin:build
bun run media:build
bun run server:dev
```

随后访问本地服务的 `/admin/` 与 `/movies/`。浏览器从同源第一方登录页建立 HttpOnly 会话，展示站登录跳回固定 `/movies/`，站点不接触密码或设备令牌。桌面登录仍只发生在系统浏览器里。

三端使用 `@assemble/media` 业务组件、`@assemble/ui` 基础组件与 `@assemble/display` 外观单例；简体中文/英语、浅色/深色/跟随系统沿用既有偏好。同源 `/admin/` 与 `/movies/` 共用浏览器偏好；桌面偏好仍只在桌面自己的环境里保存。

### 从 Jarvis 线上只读导入

2026-11-26 用户明确要求获取全部线上影视资料，包含已缓存的数据和封面，覆盖最初“不迁移片库”的约定；账号、认证关联、站点配置仍排除。导出器只读打开源 SQLite，对影视表建立一致快照，并核对读取前后的业务数据与文件状态；不修改源库、源图片、源服务或 `R:\jarvis`。旧任务保留业务历史但去除认证会话关联，不在新系统重放旧任务。

```sh
# 在能读取源数据的维护环境运行；三条路径都必须显式指定，输出目录不能已存在。
bun scripts/media/export-jarvis.ts <源数据库> <源影视目录> <新导出目录>
# 缺省只校验，不连接目标数据库；容器可将导出目录只读挂载为 /import。
assemble-server import-media-archive <导出目录>
# 备份、停目标服务后，使用正常的受保护环境与目标数据卷运行。
assemble-server import-media-archive <导出目录> --apply
```

导出包只包含影视业务表和整个影视目录，文件按 SHA-256 内容寻址。导入先核对所有文件的长度、摘要、图片解码、元数据与跨表引用，再以单事务发布。目标必须没有影视条目、资产、合集及其他导入记录；相同清单指纹重复执行只回报已导入，不覆盖后续修改。其他输入被拒绝后没有部分条目。默认校验命令连迁移都不执行，`--apply` 才加载配置和迁移。

新增 `0010_media_archive_import.sql`，不修改旧迁移。条目 ID、版本、登记/更新时间、观看日期/状态、观后感、备注、磁力、演员顺序与来源关联保留；合集顺序和指定封面保留。新片库的观看日期是 `YYYY-MM-DD`，旧时间戳按原站固定 `Asia/Shanghai` 的显示规则转换，不能直接截取 UTC 日期；原始时间戳及 `watched_order` 仍完整保存在原始业务行中，与新站语言无关。同摘要原图归并为一个工作资产，现有缩略图直接沿用，缺失尺寸才补生成；小图已经符合目标尺寸时复用原字节。所有源文件（包括原缩略图和旧影视归档）另在 `media_import_files` 保留逐文件内容及摘要；原始业务行、额外演员身份和原缓存结构保存在受保护的导入清单中，没有原始资料的公开下载 API。

缓存资料保存为持久来源快照，详情读取与后续来源导入可直接复用，无需重新联网。源过期时间保留作来源记录，不声称快照是最新资料。只允许不含私人内容的共享缓存；当前导入器拒绝私人范围，不能凭同邮箱映射旧账户。缓存图片有独立公开引用，保全用的资产引用只阻止清理，不授予 HTTP 读取权限。匿名仍看不到磁力和管理员备注，私人规则不变。

在小内存服务器上先以独立、断网、限制内存与 CPU 的容器试导入数据库备份，再维护正式目标；没有必要停 Jarvis。原始文件和正常图片都进入目标 SQLite，备份必须覆盖数据库、现有文件内容目录和配置，预留 SQLite 事务及 WAL 空间。新库已升级迁移后不能直接运行旧镜像；回滚须同时恢复导入前完整数据备份与镜像配置。导出包和备份只保存在受保护运维目录，不能提交 Git、复制到静态资源目录或输出记录原文。

### 管理、导入与失败恢复

管理员在共享片库搜索已有条目后，可以手工添加，或选择 TMDB/豆瓣搜索、核对来源详情再导入。桌面相同步骤只写入本人的私人片库，不改变共享库；同一来源作品在共享与不同私人片库内分别去重。

编辑维护观看状态、日期、观后感、备注与磁力。保存、删除和封面选择都带版本号；出现冲突时先核对最新条目，不能用旧版本强制覆盖。表单保留当前输入，明确点击“载入最新资料”才替换草稿。

导入任务按实际阶段显示“读取资料”“下载并校验图片”“保存条目”。项目数量未知时不显示百分比，已知时只显示当前阶段的实际数量。关闭导入窗口只停止本次轮询，服务端任务继续；同一账户、同一 Workspace 内重新打开可继续查看原任务。页面导航或进程重启不会持久化界面的任务选择，不能承诺自动续开弹窗。

任务请求的响应丢失、无法确定是否已入队时沿用原 requestId；已确认失败、中断或取消后，用户明确重试使用新 requestId。服务端重启后将原 running 任务标为 interrupted，原 queued 任务重新调度；每次执行仍要核验原账户、凭据和权限是否有效。不能凭本地旧登录让任务继续写入。

图集从条目关联的资料源同步，不让页面提交任意远程地址。来源下载、图片解码或校验失败时保留明确错误；只有已校验且有引用权限的资产可显示和设为封面。磁力只存储和复制，不在服务端下载其内容。
