# 网络文件下载

桌面侧栏的“网络文件下载”中，M3U8 与抖音在本机执行，无需登录；磁力通过 Assemble 服务器下载，需要已验证账户登录。页面名称仅保留在面包屑，“新建下载”“选择文件夹”两个小按钮放在“下载任务”卡片右上角，保存位置列在任务标题下。新建弹窗里选择 M3U8、抖音或磁力链，粘贴地址并解析，再选择画质或文件开始下载。两处下拉使用共享 shadcn Select；关掉弹窗可保留当前草稿，开始成功后弹窗自动关闭。页面只列任务、真实进度和保存位置。

视频下载、合并和校验在当前电脑的 Rust 侧执行，云服务器的 FFmpeg 不参与。磁力的节点发现、元数据和 BT 下载在服务器执行，再经 HTTPS 保存到本机；不经过设备传输或云盘的 100 MB 单文件接口。

## 磁力链下载

2026-11-28 用户确认改为服务器解析、下载并经 HTTPS 回传，取消 Mac 直连设置。选择磁力链、粘贴 `magnet:` 后，服务器最多用 90 秒获取真实文件列表，可取消；勾选所需文件后开始。任务仍与视频共用本机队列，不需要 FFmpeg，保存原格式。

进度先显示“服务器下载”，完成 BT 后显示“正在保存到本机”。每任务服务器上传限 256 KiB/秒，完成即停；暂停和正常退出请求停止服务器会话，异常断线最多 15 秒后暂停。服务器和 Mac 重启都先暂停，点击继续才恢复。缓存 24 小时未续期会取消清理，需重新开始；已下载到本机的内容不会因此删除。

服务器只向所属账户返回任务、元数据、清单与分片，不借用管理员 DHT 观测。原始磁力及 Tracker 参数不写服务器数据库或日志；客户端恢复来源仍只进系统钥匙串，普通历史只存去掉外层参数的元数据、选择和内部发布记录。旧本机任务继续时自动转为服务器下载，已有缓存按 HTTPS 清单重新校验后复用；旧直连字段只兼容读取，不再启用本机 BT。

HTTPS 每片 4 MiB，逐片及整文件 SHA-256 校验，长度或摘要不一致就停止，不发布文件。重启后复用已校验分片，缺失或损坏的部分重新接收。最终仍先暂存、校验，再无覆盖发布，同名自动改名。取消只清理本任务缓存和来源，已发布文件保留；本机确认完整落盘后服务器清理临时文件。清理失败保留预留并后台重试。

支持公开 BitTorrent v1（含 v1 的混合链接），拒绝纯 v2、私有种子及非公网节点。元数据最多 4 MiB、10,000 文件，所选大小仍受服务器配额和磁盘余量限制：每任务按两份缓存预留，计入全站存储预算；每账户活跃任务合计另受 `ASSEMBLE_DRIVE_QUOTA_BYTES` 限制，默认 2 GiB。账户最多 8 个活跃任务，全站最多 128 个，服务器同时执行 4 个 BT、解析 2 个元数据。本机最多保存 100 条磁力历史，未完成任务占二十个队列名额中的一个。

### 公共 Tracker 池

服务端复用经过筛选的公共池，最多 8 UDP、4 HTTPS，来源及初次筛选见[实施报告](../reports/2026-11-28-magnet-trackers.md)。固定公网地址的 HTTP(S)/UDP 引导提供初始节点，再由受限 DHT 和 PEX 补充；引擎 BT 数据连接使用公网正向列表，不开放入站、UPnP 或局域网发现。公共 Tracker 只帮助发现节点，不提供内容带宽，也不能保证资源有种。

缓存不保存查询参数或凭据，超过 24 小时后台刷新，失败保留最后有效池，至少间隔十分钟重试；候选、响应大小、并发及探测时间有上限。用户链接自带 Tracker 仍最多 16 个、单项 2 KiB，参数仅在当前解析的 Rust 内存中。所有连接固定已校验公网地址，拒绝重定向到任意来源。服务器恢复使用裸信息哈希和公共池，不保存原链接。解析阶段握手成功的节点会优先传给下载；节点缓存只在 Rust 内存里，最多 128 组、每组 64 个，十分钟过期。服务重启直接校验已保存的元数据与文件缓存，继续寻找数据节点，无需重复解析。受限 DHT 持续接收新节点，经进程内随机回环 UDP Tracker 交给引擎；它不开放公网端口，也不接收用户指定地址。

设计与限额见[决策 0019](../decisions/0019-hosted-magnet-downloads.md)；[决策 0018](../decisions/0018-magnet-local-downloads.md)保留本机 BT 方案和 Mac 网络对照的历史原因。本轮先验 Mac，Windows 不做专项验收。

## 本机媒体工具

视频下载需要本机安装 FFmpeg 与 ffprobe，磁力下载不需要。按以下顺序查找：各自的 `ASSEMBLE_FFMPEG_PATH` / `ASSEMBLE_FFPROBE_PATH`、桌面可执行文件同目录、系统 PATH，最后是几个常见的安装位置（用户目录下的 `.local/bin`；macOS 上另有 `/opt/homebrew/bin` 与 `/usr/local/bin`）。两者都找到才允许开始视频下载；安装后重启应用。路径只在 Rust 内部使用。

最后那一步是 2026-11-26 加的。从启动台、托盘或开机启动项起来的应用拿不到你在终端里设的 PATH——macOS 上 launchd 只给系统的那几个目录——而 Homebrew 和不少工具正是装在那些位置里。那天在这台 Mac 上就是这样：终端里找得到 FFmpeg 9，装好的应用却找不到。四种先后关系都有单元测试（`media.rs`）。

目前没有将这两个工具捆绑进正式安装包，也未更改安装包发布流程。分平台固定版本、来源校验与许可证随包分发仍列在下载功能计划中，不能把开发机已有工具当成安装包自带。

## 支持范围

- M3U8 支持带 `ENDLIST` 的点播、主清单画质、相对网址、TS、fMP4 初始化片段、字节范围、独立音轨和普通 AES-128 密钥。不支持直播、DRM 与 SAMPLE-AES。
- 本地 M3U8 点击“选择 M3U8 文件”导入，先直接选择文件即可；其中已有完整视频链接时无需再填地址。如果文件里的链接不完整，再在同一个“M3U8 下载链接”框填写下载该文件的链接并重新选择文件，也可用浏览器插件直接获取来源。这个链接指向 M3U8 文件，不是视频播放网页；只下载 HTTP(S) 内容，不读取文件里指定的本地路径。
- 来源网页可选，供需要 Referer 的公开清单使用；不提供任意请求头或 Cookie 输入。
- 抖音接受公开视频网址、含 `modal_id` 的网址、短链与整段分享文字。只解析目标视频，不抓取推荐视频或用户列表。图集、需要登录或受限的视频会失败。
- 首版最多同时运行两个任务、排队二十个；每个视频任务最多 10 GiB，媒体清单最多 20,000 分片，清单元数据最多 4 MiB。视频分片有有限重试，不支持视频跨重启断点续传；磁力续传见上节。
- 下载目录所在的磁盘至少要剩 200 MiB 才开始写，已知道要写多少时还得放得下那一份；排队中的任务轮到自己时再看一眼。点播清单的总大小事先不知道，所以开始之后仍然可能写满：那时候报"磁盘空间不够"（`DOWNLOAD_NO_SPACE`），不和别的存储故障混在一起。合并还要再写一份成品，所以不是"刚好放得下"就够。规则在 `space.rs`。查询前确认目录存在，已有下载目录查询它自身的磁盘；避免 Windows 对缺失目录仍返回卷容量，或将挂载目录误查为父目录所在的磁盘。

成功任务可打开视频或定位文件；取消和失败任务可在当前进程内重试。来源过期需重新解析。重启时，未完成的视频历史标为中断，需重新输入来源。磁力历史恢复为暂停，可继续。

## 文件与凭据边界

默认保存在系统下载目录下的 `Assemble/网络下载`；可以用系统选择器更换目录。界面只显示文件夹简称，文件操作只传任务标识。下载和合并先放在该目录的独立暂存子目录，ffprobe 确认真实 MP4 视频后才用同卷硬链接原子发布；同名自动加序号，绝不覆盖。不支持硬链接的文件系统明确报保存失败。

进程被杀掉的时候暂存目录会留下来，里面可能是好几个 G 的分片。应用启动时、窗口开出来之前，会把视频暂存目录清掉（`DownloadManager::sweep_staging`）：只删名字对得上的目录，目录先过边界检查，不跟着链接走；下载好的文件和别的目录不动。

清单、重定向、分片和密钥均由 Rust 检查协议、标准 HTTP(S) 端口、公网地址并固定连接。FFmpeg 仅处理重建的本地清单及本任务文件，关闭网络协议；分片解封装只允许 MPEG-TS、MOV/MP4 和 AAC。不会读取系统浏览器 Cookie、密码或 Assemble 的设备令牌。

下载客户端不继承环境 HTTP 代理，以免代理替换已检查的 DNS 连接。系统 DNS 全部返回代理软件的 `198.18.0.0/15` Fake-IP 地址时，才通过固定 Cloudflare DoH 地址查询真实公网 IPv4，最多缓存三十秒。它只收到目标域名；完整网址和签名参数不会发给 DNS 服务。真实私网解析、直接输入的保留 IP 和重定向到私网仍会被拒绝。DoH 不可达时明确失败。[Cloudflare DoH JSON 接口](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)

视频完整来源、签名网址、匿名抖音 Cookie 和密钥只留在 Rust 内存或当前任务暂存文件，不写任务展示状态或历史。磁力恢复来源只进系统钥匙串。私有历史文件保存展示字段和已发布文件的位置；普通失败仅向界面返回稳定错误码。没有来源摘要时，本地计算的摘要不能证明上游内容真实，完整性还依赖声明长度、范围、所有资源成功和媒体检查。

## 验证与后续入口

自动化检查运行 `bun run verify`。真实媒体测试另需本机工具，明确运行：

```powershell
cargo test -p assemble-download real_media_pipeline -- --ignored
```

它实际生成含声音的测试视频，分别经 TS、fMP4 单文件字节范围、AES-128 和独立音轨清单走完整下载、合并、校验与发布，检查音视频流、旧文件不覆盖和暂存清理。普通测试机缺工具不会把这项伪装为通过；默认测试将其标为需单独运行。

2026-11-26 在 macOS 上用本机的 FFmpeg 与 ffprobe 9.0.1 真跑过一次，通过（1.4 秒）。同一天补的几条规矩各有单元测试：磁盘余量怎么算、写满是它自己的一个错、崩溃留下的暂存目录被清掉而别的都不动、PATH 里找不到时去常见位置找。**装好的应用里还没有人在 macOS 上点过这一页**，扩展也还没有装进日常的 Chrome。

在 macOS 上把开发版插件装进日常 Chrome（2026-11-26 核对过安装脚本，**还没有人真做过**；Windows 的真实链路验过，见[插件说明](../../apps/browser-extension/README.md)）：

```sh
bun install --frozen-lockfile
bun run browser:build                                                   # 插件本体，产出到 apps/browser-extension/dist
cargo build --release -p assemble-desktop --bin assemble-browser-host   # 本机桥接的宿主程序
bun run browser:install --desktop /Applications/Assemble.app/Contents/MacOS/assemble-desktop --dry-run
bun run browser:install --desktop /Applications/Assemble.app/Contents/MacOS/assemble-desktop
```

最后两条会写两处用户级的东西：Chrome 的 `NativeMessagingHosts` 目录里一份清单，以及 `~/Library/Application Support/Assemble/BrowserConnector/` 下宿主程序的一份副本和非敏感配置。然后在 Chrome 打开 `chrome://extensions`，开"开发者模式"，"加载已解压的扩展程序"选 `apps/browser-extension/dist`。桌面上那份 Assemble 必须是带下载入口的新版本；旧版本只有插件是用不了的。装好之后拔掉再插一次插件（关掉再打开），点一个视频页上的 Assemble 图标试下载。

仅针对公开、可分享来源的手工验证可运行 `cargo run -p assemble-download --example inspect -- <公开地址>`；追加 `--download` 会实际下载到临时目录、校验音视频流后清理。不要把带私密签名的地址放进命令行或终端历史。

Chrome 插件已实现主动检测网页视频/M3U8，并可将所选来源加入同一个桌面下载队列。它经受限制的原生宿主交接，临时连接凭据仅在系统凭据库与 Rust 内部；插件不接触 Assemble 登录凭据。MP4/MOV/M4V/WebM 直链先核对真实容器，再无转码封装为 MP4；浏览器提交主清单时使用最高带宽版本。加载、原生组件登记、支持范围与真实 Chrome 验证见[插件说明](../../apps/browser-extension/README.md)。当前是开发版，尚未安装到日常 Chrome 或上架商店，MCP 本机下载入口已实现，使用方式与验证边界见下节。

## 助手发起本机下载（2026-11-27）

桌面应用运行时，MCP 提供 assemble_download_preview、assemble_download_start、assemble_download_status，以及 assemble_download_pause、assemble_download_resume、assemble_download_cancel 六个具名工具：先解析公开来源，再选择预览里的清晰度或文件标识开始，最后按任务标识查询。磁力暂停、继续沿用同一任务，幂等键包含文件选择。任务统一由桌面队列编排，磁力的 BT 交换在服务器执行，结果只含安全文件名，不含来源签名网址、凭据或完整本机路径。关闭应用会如实报告未连接，不自动启动。

在本机设置中可关闭“允许助手在这台电脑下载”，默认开启，保存失败时开关保持原值。助手任务在下载列表标记“由助手发起”；本机保存目录沿用系统选择器设置。开关、挑战认证、两步开始、幂等和安全投影均有自动化测试；Windows/macOS 真人经对话开始并播放下载视频仍待新版本验收。此段描述源码能力，不表示当前安装版或正式安装包已经更新。

边界见[决策 0016](../decisions/0016-assistant-local-downloads.md)。

### 磁力验证（2026-11-27）

`cargo test -p assemble-download magnet::` 默认运行真实回环 BT 测试，不需要公网资源、FFmpeg 或真实系统钥匙串：交换元数据和分片，选择文件与空文件，暂停后销毁管理器，破坏缓存再恢复，逐字节核对成品；检查未选文件不发布、同名不覆盖、完成后缓存和来源清理、暂停及完成后连接不再传输。另覆盖中断历史恢复、取消清理、解析取消、路径/符号链接、所选容量及凭据分段。桌面界面与桥接测试覆盖无 FFmpeg 仍可选择文件、只提交所选标识、具名暂停/继续和状态契约；MCP 走实际挑战认证和工具协议，覆盖 512 个文件的大清单；预览通道独立保留 100 秒与 8 MiB 应答预算，避免旧视频摘要的 40 秒 / 8 KiB 限制提前截断磁力元数据。

Windows 真机 BT 下载与正式安装包发布仍待验收。macOS 上的本机 BT 测试、全仓自动化和真实应用启动分别记录，不能相互替代。

2026-11-28 在 macOS 使用 `bun run build -- --debug --bundles app --config ...` 构建独立测试应用（标识 `com.puzzlefuzzy.assemble.magnet-test`，连接隔离的回环服务地址），实际打开窗口和网络下载入口，选择磁力链，核对上传策略与重启继续提示；无效输入经真实 IPC 显示固定中文错误。通过菜单快捷键正常退出后，系统确认测试应用已停止。原安装版与登录数据未替换。此项验证窗口和生命周期，不代表在真实窗口内完成了公网 BT 下载；字节级 BT 流程由回环种子测试覆盖。

### 服务器磁力回归（2026-11-28）

`cargo test -p assemble-server --lib magnets::tests` 使用真实回环种子和 HTTP：核对元数据、所选文件、暂停不增长、15 秒租约机制、服务重启、账户隔离、取消先于创建和缓存释放。Mac 队列同样走实际客户端：暂停退出、重新打开、拒绝故障注入的坏分片、复用先前已校验分片，并核对成品摘要。`assemble-download` 的公网正向列表测试另确认内网、回环、映射地址、文档和组播不能用于 BT 数据连接。实际公网下载和安装结果单独记录，不能以这些测试替代。
