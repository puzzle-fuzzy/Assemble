# 浏览器身份页的共享界面

2026-11-26 用户要求浏览器登录、设备授权及相关账户页面与管理端、桌面端对齐。本次只处理这些网页的界面，不涉及另一位开发者负责的 iOS 真机与推送。

登录、管理员登录、注册、找回密码、邮箱验证、GitHub 注册补充信息、账户及结果页使用同一份 `packages/ui` 的 shadcn 配色、Geist 字体、卡片、Field、Input、Button、Alert、Separator 和头像样式。授权页将账户、设备和系统分项展示，确认与取消并列。页面维持简洁的单列布局，长账户页可以滚动，窄窗口不会横向溢出。

这些页面仍由 Rust 渲染并提交原生表单；登录、授权和账户页不新增浏览器脚本。现有 `/web/verify.js` 仅继续处理邮件链接片段。没有增加密码或 Cookie 的前端读取、凭据接口、第三方资源请求或前端登录请求。

## 样式如何复用

`packages/ui/scripts/build-server.ts` 在构建时渲染现有共享组件，导出静态 HTML 属性，并由同一 Tailwind 入口编译主题与布局。结果和字体许可证保存于 `apps/server/src/web_ui/generated/`，经 `include_str!` / `include_bytes!` 进入服务端二进制。Rust 只组合这些属性与经过转义的动态文字，不另行维护一套组件配色或圆角。

```powershell
bun run ui:server       # 共享组件或身份页布局变化后更新产物
bun run ui:server:check # 只核对是否过期，不写文件
```

生成物提交到版本库，独立运行 `cargo build -p assemble-server` 不依赖先启动 Vite。完整 `bun run verify` 会核对生成物，防止共享组件更新后身份页继续使用旧样式。不要直接编辑生成的 CSS、属性或字体。

页面 CSS 仍以固定内容哈希进入 CSP，不开放内联脚本或 `unsafe-inline`。`/web/ui/` 只服务内嵌字体及许可证的精确白名单，不读取磁盘路径；字体同源、带 ETag，未携带用户数据。授权页继续仅允许当前有效回环端口，GitHub 绑定页继续仅额外允许固定 GitHub 来源。

页面文案仍沿用当前中文身份流程，外观跟随系统。管理端、桌面端和影视站的语言、手动主题偏好及其存储不变；身份页没有增加偏好脚本或语言菜单，避免中文页面被错误标记为另一种语言。

## 独立验收

```powershell
cargo build -p assemble-server --example web-ui-preview
bun scripts/web-ui/smoke.ts
```

本机 Windows 验收器启动独立回环服务、临时 SQLite 与合成账户，再用独立 Chrome 资料检查浅色、深色和窄窗口。预览账户密码只在 Rust 内存内生成和使用，不交给浏览器脚本；不会读取受保护配置或操作正式账户。示例中的额外预览路由只存在于示例可执行文件，不进入正式服务。

验收包含原生登录失败提示、注册/找回/验证界面、GitHub 信息补充、账户与退出、真实授权确认/取消以及跨回环端口跳转，检查字体加载、CSP 和横向溢出。邮件验证确认页和 GitHub 补充页使用展示夹具；不发送真实邮件或完成第三方 OAuth。截图保留在忽略目录 `.artifacts/web-ui/`，结束时关闭测试进程并清理临时数据库。此自动化不代表 iOS 真机或正式用户登录验收。
