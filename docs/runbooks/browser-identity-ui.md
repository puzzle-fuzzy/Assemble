# 浏览器身份页的共享界面

2026-11-26 用户要求浏览器登录、设备授权及相关账户页面与管理端、桌面端对齐。本次只处理这些网页的界面，不涉及另一位开发者负责的 iOS 真机与推送。

登录、管理员登录、注册、找回密码、邮箱验证、GitHub 注册补充信息及账户页使用同一份 `packages/ui` 的 shadcn 配色、Geist 字体、卡片、Field、Input、Button、Alert、Separator 和头像样式。页面维持简洁的单列布局，长账户页可以滚动，窄窗口不会横向溢出。

用户随后指定以官方 `login-03` 为登录、注册和填写验证码/新密码页面的参考：浅灰背景、居中品牌、窄卡片与居中标题说明；GitHub 入口置于邮箱表单之前，密码标签右侧提供找回链接。注册无需邀请码，发送邮件、验证和设置密码的顺序不变；旧账户兼容路由保留，但登录和 GitHub 注册页不再展示旧账号迁移入口，符合此前正式账号从零开始的要求。

用户随后纠正了文案调整范围：仅删除普通登录页中的“使用邮箱或 GitHub 账户登录”这一行。其余说明、标签、按钮、错误提示及管理端中英文文案均保留 `login-03` 调整后的原文，不做全面精简。用户要求暂不推送，修改只在独立工作区本地提交。

只有文字、跳转或确认操作的页面按用户截图使用共享 `Empty`：白色背景、居中图标、标题、说明和必要按钮，不显示卡片或空的字段分组。覆盖邮件发送结果、退出、错误/完成结果、设备登录授权，以及无需设置密码的邮箱确认。设备和邮箱确认仍以携带隐藏防伪字段的原生 POST 提交，不能为追求“无表单外观”改成 GET 或自动确认。

这些页面仍由 Rust 渲染并提交原生表单；登录、授权和账户页不新增浏览器脚本。现有 `/web/verify.js` 仅继续处理邮件链接片段。没有增加密码或 Cookie 的前端读取、凭据接口、第三方资源请求或前端登录请求。

## 样式如何复用

`packages/ui/scripts/build-server.ts` 在构建时渲染现有共享组件，导出静态 HTML 属性，并由同一 Tailwind 入口编译主题与布局。结果和字体许可证保存于 `apps/server/src/web_ui/generated/`，经 `include_str!` / `include_bytes!` 进入服务端二进制。Rust 只组合这些属性与经过转义的动态文字，不另行维护一套组件配色或圆角。

```powershell
bun run ui:server       # 共享组件或身份页布局变化后更新产物
bun run ui:server:check # 只核对是否过期，不写文件
```

生成物提交到版本库，独立运行 `cargo build -p assemble-server` 不依赖先启动 Vite。完整 `bun run verify` 会核对生成物，防止共享组件更新后身份页继续使用旧样式。不要直接编辑生成的 CSS、属性或字体。

页面 CSS 仍以固定内容哈希进入 CSP，不开放内联脚本或 `unsafe-inline`。`/web/ui/` 只服务内嵌字体及许可证的精确白名单，不读取磁盘路径；字体同源、带 ETag，未携带用户数据。授权页继续仅允许当前有效回环端口，GitHub 绑定页继续仅额外允许固定 GitHub 来源。

页面文案仍沿用当前中文身份流程，外观跟随系统。管理端、桌面端和影视站的语言、手动主题偏好及其存储不变；身份页没有增加偏好脚本或语言菜单，避免中文页面被错误标记为另一种语言。

## 添加手机：扫码配对页（2026-11-26）

账户页多了一栏"手机"和"添加手机"，进到 `/web/pairing`。规则见[决策 0014](../decisions/0014-iphone-client.md)。这一页和别的身份页不一样的地方：

- 不用脚本。等手机来扫的那一段靠 `<meta http-equiv="refresh">` 每两秒重新载入；二维码是服务端画的一段内联 SVG。页面共用的内容安全策略原样不变，所以**样式只能用属性**（`fill`、`width`），不能有 `style=`，二维码的白底也是为此写死的。
- 页面上同时给出二维码编码的那一串地址（`assemble://pair?ticket=…`），扫不了码的人可以照着粘贴；模拟器里的手机应用就靠它。测试时从页面上取这一串，不用解码二维码。
- 票据库里只存摘要。还没被认领的那张只在服务进程的内存里留三分钟；重启过，或者页面开得太久，会看到"这次配对已作废"。
- 真机上看这一页的步骤：用一个本机的一次性服务端和它自带的测试账户登录（邮箱要标成已验证，配对和桌面授权一样只对验证过的账户开放），账户页 →"添加手机"→"显示二维码"。

在 Mac 上做这一遍的办法（2026-11-26 走过）：`cargo build -p assemble-server`，用临时的数据目录起 `assemble-server serve`（`ASSEMBLE_DATA_DIR`、`ASSEMBLE_PUBLIC_ORIGIN`、`ASSEMBLE_ADDR` 都指到回环地址的另一个端口），`create-account` 建一个测试账户（密码经标准输入），再用 `python3` 的 `sqlite3` 把它的邮箱标成已验证；然后用 ZCode 的内置浏览器照上面的步骤走，"手机"那一侧用 `python3` 直接调两个接口（认领时字段名是 `codeChallenge`、`deviceName`，问结果是 `codeVerifier`）。内置浏览器里自动化的点击有时不提交表单，用页面里的 `form.requestSubmit()`；带按钮值的那个要用 `requestSubmit(button)`，`choice=allow` 才会带上。做完停服务端、删临时目录。

这一次的结果：二维码在深色模式下是白底黑格、270 像素见方；自动刷新之后二维码还在；认领之后页面换成"核对数字"，显示的六位数字和手机拿到的一致；点"允许"之后手机拿到令牌，用它调 `/v1/me` 成功，票据再用一次被拒；最后一页是"添加好了"。响应头里的内容安全策略和别的页面一样。真机上用摄像头扫还没有做过。
