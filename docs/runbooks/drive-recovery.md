# 云盘本机恢复与下载续传（N4.2）

2026-11-28。源码与自动化、Windows 隔离窗口及镜像启动验收已完成；尚未正式部署或发布桌面签名更新。N4.1 服务端迁移固定为 0017，本包不新增或修改迁移。iOS、APNs、推送、设备中转续传及助手上传权限均未改动。

## 操作

云盘上传和取回仍使用现有传输行。重开应用后，可恢复任务先显示暂停，用户点击继续才联网，不自动上传旧路径。暂停、继续、取消按钮复用共享组件，可访问名称包含完整文件名，中英同步。完成时通过不抢焦点的状态区域告知辅助技术。

原文件丢失或内容变化时暂停，并提供系统文件选择器。界面只传任务标识；选中的文件必须与原长度和摘要一致，匹配后仍由用户点击继续。稳定上传请求键保留，改名或移动原件不会新建第二个云盘对象；服务端已经完成且回执丢失时，即使原件不在，也可以读回真实完成回执。

接收位置改变、不可用或暂存损坏时停止，不能将旧片拼到另一个目录。失败后由用户重新发起下载。取消/完成的暂存清理有本机持久记录，失败退避重试；已经完成的目标文件不被清理。暂停不产生额外通知。

## 私有恢复日志

应用数据目录新增 `transfer-recovery.json`，独立于 `transfers.json` 历史。版本 1 按服务来源、账户、发起设备隔离，最多 20 个归属、合计 200 个任务，每个归属最多 100 个。日志读入上限 4 MiB，原子私有写入；没有密码、令牌或 Cookie。恢复日志中的源路径、分片摘要、请求键和暂存位置仅由 Rust 使用，不进入传输快照或具名命令返回值。

工作意图先持久化再执行网络/文件副作用。写入失败停止工作，保留原日志；损坏或超前版本不当空队列覆盖，也不清扫恢复暂存。退出和失效立即停止本机会话并隐藏记录，日志保留给原归属；重新授权的新设备标识不能接管原设备上传。旧历史仍只保存展示与已完成文件定位，不自动转换为工作队列。

旧服务的普通完整传输不进入跨进程恢复日志，不把丢失响应的完整 POST 重放成“续传”。续传会话到期或目标祖先变化仍使用 N4.1 固定失败，不换请求键或悄悄回退到根目录。

## 下载契约

- 新增 `GET /v1/drive/files/{id}`，返回既有 `DriveFile`，每次检查本人身份和活动文件。回收、删除、停用、撤销或其他账户不能读取。
- 原内容入口使用不可变 SHA-256 的带引号强 `ETag`。匹配的 `If-Range` 才处理区间，弱值或不匹配值返回完整表示；权限仍先检查。
- 客户端单次最多读取 1 MiB，带有界 `Range`、强 `If-Range` 和 identity 编码。仅接受精确的 206、Content-Range、偏移、总长度、强 ETag、实际字节数；200、416、弱/变化验证值不能追加。首片收到完整 200 才允许走旧完整下载，已经存在的检查点不降级拼接。依据 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-range)。
- 每片先同步到同卷私有 `.assemble-resume-<随机>/`，再提交检查点。恢复时读回并校验已确认片；无确认片允许重写，同片不叠加。
- 最后重新核对服务端访问、接收目录、片长度、片摘要与整文件摘要，才使用严格硬链接无覆盖发布。不支持该发布方式的文件系统明确失败；已有不同内容拒绝覆盖，同名同内容可幂等确认发布后的崩溃空窗。
- 每次重开暂存或发布都重新核对规范接收目录、名称、普通文件及链接边界。启动先读所有归属的有效引用；仅在受控命名空间回收超过一天且无引用的目录，不递归删除任意用户目录。

具名 `pause_transfer` / `resume_transfer` 同时服务云盘上传和下载；新增 `relocate_transfer(transferId)` 仅允许已登录主窗口或发送面板使用系统选择器。界面没有通用路径、网络或文件权限。

自动化包括真实 HTTP 区间矩阵、真实服务端访问拒绝、私有日志版本与归属隔离、重建桌面状态后上传重新定位和下载继续、摘要校验及重复发布。窗口、镜像、完整验证和 CI 结果见本机 `data/local/n42/acceptance.md`；没有完成的结果不以计划替代。

发布顺序仍为先服务端、后由发布 Mac 签名桌面更新。正式服务和已安装应用在本轮保持原发布状态；Windows 本机证据不能替代 macOS WebView 或两台真实设备验收。
