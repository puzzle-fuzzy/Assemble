# 2026-11-27：影视展示站分页、详情与性能

用户反馈 `/movies/?plannedPage=4` 翻页像整页切换，要求提高 Lighthouse 分数；随后要求详情与只读参考 Jarvis 保持一致，包含轮播和封面点击预览，并提供《死亡诗社》演员缺图占位比照片高的截图。

本次修改仅涉及 Assemble 影视展示站及它的静态资源响应，不修改 Jarvis、正式账户或影视数据。最初的新版证据来自本地构建；2026-11-27 用户进一步要求提交、推送、正式部署并复测 HTTPS 页面，实际结果在完成后追加到本文。

## 行为与实际浏览器核对

- 翻页只请求目标分区，等待时保留原网格、分页器与焦点，阻止重复点击；类型、账户和请求中止的回归另由测试覆盖。
- Chrome 从第 4 页到第 5 页再返回第 4 页，分页器相对视口位置均为 `473.1953125px`，滚动位置均为 `576px`。页面未重新导航。
- 详情使用左侧海报与右侧资料，390px 窄屏改为上下排列，无横向溢出。
- 点击封面可查看原图，打开从原位放大，关闭缩回，结束后没有临时动画层或对话框残留，焦点返回原按钮。单图不显示轮播控件。
- 独立三图夹具实际核对按钮、左右键循环、缩略图直达及窄屏排版。夹具只替换本机一个图集响应，三张图片来自已公开共享资产，不代表正式条目的实际图集。
- 《死亡诗社》的 20 个演员头像，包括 Joe Aufiery、Matt Carey、Jane Moore、Colin Irving 四个缺图占位，外框与内部内容实测全部为 `48 × 72px`。

## Lighthouse

Lighthouse 13.6.0、Chrome 158，默认移动配置及 `--preset=desktop`，保留性能、无障碍、最佳实践、SEO 四类，没有禁用审计或调整评分权重。

开始时直接审计正式 HTTPS 页面得到移动性能 92、桌面性能 93，两端其余评分为 100 / 96 / 100。移动 LCP 2.652 秒、CLS 0.1300；桌面 LCP 0.549 秒、CLS 0.1594。最佳实践扣分来自 favicon 404。

本地 HTTP/1.1、代理时序与线上 HTTPS/HTTP/2 有明显区别，修改前分数也不同。因此只能比较同环境前后结果，不能用本地新版分数宣称线上已经达到相同分数。部署后应重新审计实际 HTTPS 地址。完整报告、网络记录、基线静态文件和本地夹具保存在忽略目录 `data/local/media-performance/`。

## 自动化与真实服务

全量类型检查、363 项 TypeScript/工具测试、全部前端构建、共享服务端 UI 产物检查、Rust 格式和全工作区 Clippy 通过；五个基础库的 Windows 目标 Clippy 通过。Rust 测试 596 通过、2 项既有忽略。变更范围内 Biome 与 `git diff --check` 通过。最终复核补测并修复了关闭途中切图取消关闭回调、原图在开场结束前失败残留动画层两种竞争。

初次 `bun run verify` 在 Biome 阶段被并行开发的 iPhone 生成物与 JSON 样本格式挡住，当时其余检查分别执行。该项工作完成独立提交、重新生成样本并排除生成物后，2026-11-27 提交前重跑完整 `bun run verify`，全部通过，用时 56.9 秒；没有将 iPhone 的未提交改动混入影视提交。

首次推送后 macOS CI 通过，Windows CI 暴露了详情首次分块加载的测试竞争：点击作品后只等固定 5ms 就查找返回链接，分块尚未加载完时会误报缺少链接。回归改为在明确时限内等待实际返回入口出现，保留原有返回 URL 断言，不改变产品行为，也不跳过测试；修复后本机完整验证再次通过，用时 57.0 秒。

另用空的一次性数据目录实际启动 Rust 服务，核对 `/healthz`、静态页面、带指纹 JS、外观脚本、favicon、缺失资源与共享 API。指纹 JS 返回一年 `immutable`，HTML/API/错误维持 `no-store`。Rust HTTP 测试额外覆盖 HEAD、304、206 与缓存排除规则。没有启动或替换桌面安装版，也没有做 Windows 真机验收。
